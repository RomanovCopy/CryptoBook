# Требования к автоматическому сбросу ключа шифрования

## 1. Назначение

Функция должна автоматически сбрасывать ключ шифрования из памяти приложения после заданного периода бездействия пользователя. Это не отдельная блокировка приложения: после сброса ключа интерфейс очищается, а доступ к зашифрованному документу восстанавливается только после повторного ввода корректного ключа.

## 2. Область действия

- Автоматический сброс запускается только если ключ шифрования был успешно введён и `IKeyProvider.HasKey == true`.
- Если ключ не введён, таймер не запускается и сброс не выполняется.
- Ручной сброс ключа должен быть доступен отдельной командой приложения, например `Ctrl+L`.
- Потеря фокуса окна сама по себе не считается бездействием.
- Блокировка Windows-сеанса, выход пользователя из сеанса, переход в сон или гибернацию должны приводить к тому же безопасному сценарию сброса.

## 3. Настройка пользователем

В настройках приложения добавить параметр:

**«Сбрасывать ключ после бездействия»**

Доступные значения:

- 1 минута;
- 5 минут;
- 10 минут;
- 15 минут;
- 30 минут;
- Никогда.

Рекомендуемое значение по умолчанию: 15 минут.

Настройка должна сохраняться в пользовательских настройках приложения. Изменение интервала не должно требовать перезапуска.

## 4. Определение бездействия

Счётчик бездействия должен сбрасываться при действиях пользователя внутри CryptoBook:

- нажатие клавиш;
- движение и нажатие мыши;
- прокрутка;
- изменение текста документа;
- команды открытия, сохранения, закрытия и переключения документа;
- завершение диалоговой операции.

Операции сохранения, открытия, шифрования и расшифровки должны временно приостанавливать автоматический таймер. После их завершения отсчёт начинается заново.

## 5. Сценарий автоматического сброса

При истечении интервала приложение выполняет операции строго в следующем порядке:

1. Переводит сервис в состояние `Resetting` и запрещает параллельные операции открытия/сохранения.
2. Определяет наличие текущего документа и его несохранённых изменений.
3. Сохраняет текущее содержимое в зашифрованный lock-снимок.
4. Проверяет, что снимок успешно записан и может быть расшифрован текущим ключом.
5. Очищает `IKeyProvider` через `Clear()`.
6. Очищает текущий `FlowDocument` и закрывает `DocumentSession`.
7. Закрывает дочерние окна, способные отображать содержимое документа.
8. Переходит в состояние `KeyReset`.

Если любой этап сохранения или проверки снимка завершился ошибкой, ключ и документ не очищаются. Пользователю показывается сообщение об ошибке, а таймер запускается заново после закрытия сообщения.

## 6. Зашифрованный lock-снимок

- Lock-снимок должен создаваться в каталоге `%LOCALAPPDATA%\\CryptoBook\\Lock\\`.
- Содержимое снимка должно сериализоваться из текущего `FlowDocument` и шифроваться текущим ключом через существующий механизм `SecureFileProcessor`.
- Снимок не должен перезаписывать исходный обычный файл (`.txt`, `.rtf`, `.xaml` и т. п.).
- Если текущий документ уже является `.cbook`, допускается атомарное сохранение в исходный файл.
- В снимке или его зашифрованных метаданных необходимо сохранить:
  - исходный путь файла;
  - имя документа;
  - идентификатор шаблона файла;
  - признак наличия несохранённых изменений.
- Обычный DPAPI recovery-снимок не заменяет lock-снимок: для восстановления после сброса требуется проверка именно ключом шифрования.
- Lock-снимок удаляется после успешного восстановления документа и подтверждения пользователем.

## 7. Восстановление после ввода ключа

После сброса приложение должно показывать отдельное окно разблокировки:

- одно поле для ключа;
- без повторного ввода ключа;
- проверка ключа расшифровкой lock-снимка до его установки как активного;
- сообщение об ошибке при неверном ключе;
- ограничение частоты повторных попыток.

После успешной проверки показывается диалог:

> Открыть последний файл «ИмяДокумента»?

Варианты ответа:

- **Открыть** — открыть последний файл через штатный механизм CryptoBook;
- **Восстановить снимок** — загрузить содержимое lock-снимка как восстановленный несохранённый документ;
- **Отмена** — оставить приложение без открытого документа.

Если исходный файл отсутствует, перемещён или недоступен, вариант «Открыть» заменяется на предложение восстановить снимок.

## 8. Состояния функции

```text
Inactive       — ключ не введён или функция отключена
Active         — ключ есть, таймер отсчитывает бездействие
Resetting      — выполняется сохранение и очистка
KeyReset       — ключ сброшен, документ очищен
Unlocking      — проверяется введённый ключ
Restoring      — восстанавливается последний документ
```

Переходы между состояниями должны быть защищены от повторного запуска. Одновременно допускается только одна операция сброса или восстановления.

## 9. Безопасность

- Ключ не должен сохраняться в пользовательских настройках, логах или незашифрованных файлах.
- После сброса необходимо очистить массивы байтов, связанные с ключом, через `CryptographicOperations.ZeroMemory` там, где это возможно.
- Парольные поля должны очищаться после завершения операции.
- Визуальное содержимое документа не должно оставаться доступным в открытых дочерних окнах.
- Ошибки не должны содержать ключ, расшифрованное содержимое или полный текст документа.

## 10. Критерии приёмки

- При отсутствии введённого ключа автоматический сброс не происходит.
- При достижении выбранного таймаута текущий документ сохраняется в зашифрованный снимок, ключ очищается, а `FlowDocument` становится пустым.
- При ошибке шифрования документ и ключ остаются доступными.
- После ввода неверного ключа документ не восстанавливается.
- После ввода верного ключа пользователь видит предложение открыть последний файл.
- При удалённом исходном файле пользователь может восстановить документ из lock-снимка.
- Любое действие пользователя сбрасывает таймер бездействия.
- Повторный запуск таймера во время сброса или восстановления невозможен.
- Настройка интервала сохраняется и применяется без перезапуска приложения.
- Сценарии блокировки Windows-сеанса и выхода из сна приводят к безопасному сбросу ключа.
