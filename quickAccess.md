# Quick Access — закреплённые документы и безопасное переключение

## 1. Цель

Предоставить пользователю простой способ быстро переходить между часто используемыми файлами через закреплённые ссылки в `SideMenu`.

CryptoBook продолжает работать только с одним загруженным документом и одним редактором. Функция не создаёт несколько `Home`, вкладки или параллельные `DocumentSession`.

Перед переходом к другому документу текущий документ должен быть безопасно сохранён. Если переключение невозможно завершить, текущий документ должен остаться открытым и неизменённым.

## 2. Основные продуктовые решения

- В приложении одновременно открыт только один редактируемый документ.
- Закреплённая ссылка — это путь к файлу, а не сохранённая сессия редактора.
- В `SideMenu` появляется отдельный динамический раздел «Закреплённые».
- Пользователь может закрепить текущий файл, открепить его и изменить порядок ссылок.
- Закреплённые файлы сохраняются между запусками приложения.
- При переключении сохраняется только изменённый (`IsDirty`) документ. Чистый документ повторно на диск не записывается.
- Открытие из закреплённой ссылки, проводника, поиска и стандартной команды Open должно использовать один общий сценарий переключения.
- Успешное переключение обновляет `DocumentSession`, заголовок окна, заголовок `SideMenu` и состояние recovery.

## 3. Пользовательский интерфейс

### 3.1. Раздел «Закреплённые»

Раздел размещается в прокручиваемой центральной области `SideMenu`, перед обычными разделами навигации или непосредственно после быстрых действий.

Каждая ссылка показывает:

- имя файла;
- родительский каталог второй, менее заметной строкой;
- пиктограмму типа документа;
- визуальный признак текущего файла;
- признак несохранённых изменений для текущего файла;
- состояние недоступного или отсутствующего файла.

Полный путь доступен во всплывающей подсказке.

Для текущего файла используется спокойное выделение: акцентная полоса, фон или маркер. Не следует одновременно применять несколько сильных визуальных эффектов.

### 3.2. Команды

Для закреплённой ссылки доступны:

- открыть или переключиться;
- открепить;
- показать в проводнике;
- повторно указать расположение отсутствующего файла;
- переместить выше или ниже; в дальнейшем это может быть заменено drag-and-drop.

Рядом с крупным заголовком текущего документа размещается кнопка-булавка:

- незакреплённый файл — «Закрепить»;
- закреплённый файл — «Открепить»;
- документ без физического пути — запуск Save As, затем закрепление после успешного сохранения.

### 3.3. Состояние переключения

Во время переключения:

- повторные команды переключения блокируются;
- выбранная ссылка показывает компактный индикатор выполнения;
- редактор не очищается заранее;
- `SideMenu` можно закрыть после успешного перехода;
- при отмене или ошибке меню остаётся в предсказуемом состоянии, а текущий файл не меняется.

## 4. Алгоритм переключения

Операция должна быть последовательной и транзакционной.

1. Нормализовать путь целевого файла.
2. Если это путь текущего документа, завершить операцию без сохранения и перезагрузки.
3. Заблокировать параллельные переключения.
4. Проверить существование и доступность целевого файла.
5. Если текущий документ изменён, сохранить его:
   - для документа с путём использовать обычное сохранение;
   - для нового документа открыть Save As;
   - при отмене, ошибке или незавершённом сохранении прекратить переключение.
6. Для защищённого целевого файла запросить и проверить его ключ только после сохранения текущего документа.
7. Подготовить новый документ отдельно, не изменяя содержимое активного `RichTextBox`.
8. После успешной подготовки атомарно заменить содержимое редактора.
9. Обновить `DocumentSession` только после успешной замены содержимого.
10. Обновить дату последнего открытия и визуальное состояние закреплённых ссылок.
11. Очистить recovery-снимок предыдущего документа, когда подтверждено его успешное сохранение.
12. Снять блокировку переключения.

Если любой шаг до фиксации нового документа завершается неудачно, пользователь остаётся в прежнем документе.

## 5. Архитектурные требования

### 5.1. Единый координатор открытия

Следует ввести единый сервис, например:

```csharp
public interface IDocumentSwitchCoordinator
{
    Task<DocumentSwitchResult> SwitchAsync(
        string targetPath,
        CancellationToken cancellationToken = default);
}
```

Через него должны работать все внутренние способы открытия документа:

- закреплённые ссылки;
- File Explorer;
- поиск workspace;
- стандартная команда Open;
- будущий список недавних документов.

Координатор отвечает за:

- защиту от потери несохранённых изменений;
- сериализацию операций;
- маршрутизацию форматов;
- работу с защищёнными файлами;
- подготовку содержимого без разрушения текущего документа;
- фиксацию нового состояния только после успешной загрузки;
- понятный результат `Success`, `Cancelled`, `Failed` или `OpenedExternally`.

ViewModel закреплённых ссылок не должна самостоятельно вызывать сохранение, расшифровку или загрузку `FlowDocument`.

### 5.2. Хранилище закреплённых документов

Следует выделить отдельный сервис, например `IPinnedDocumentStore`.

Рекомендуемые данные записи:

```text
Path
PinnedAtUtc
LastOpenedAtUtc
SortOrder
```

Допустимо позднее добавить пользовательский псевдоним и состояние навигации по документу.

Хранилище не должно содержать:

- пароли или ключи;
- извлечённый текст;
- фрагменты документа;
- расшифрованные временные данные;
- миниатюры защищённых документов.

Рекомендуемый формат — небольшой версионируемый JSON в каталоге данных CryptoBook внутри `%LocalAppData%` с атомарной записью через временный файл.

### 5.3. Нормализация и уникальность

- Сохранять полный путь, полученный через `Path.GetFullPath`.
- На Windows сравнивать пути через `StringComparer.OrdinalIgnoreCase`.
- Не допускать дубликатов одного нормализованного пути.
- Не считать различие регистра символов отдельным файлом.
- Не добавлять запись до успешного первого сохранения документа.

## 6. Защищённые документы

- Текущий защищённый документ должен сохраняться с его действующим ключом до запроса ключа следующего файла.
- Ошибка или отмена ввода ключа целевого файла не должна закрывать или очищать текущий документ.
- Ключ, введённый для неудачного переключения, не должен затем молча использоваться для сохранения предыдущего документа.
- Временный расшифрованный файл должен удаляться после подготовки внутреннего документа или ошибки.
- Закрепление хранит только путь и безопасные метаданные.
- Поведение файлов с разными паролями должно быть покрыто отдельными тестами.

## 7. Переименование, удаление и перемещение

### Переименование внутри CryptoBook

После успешного переименования открытого документа соответствующая закреплённая ссылка обновляется на новый путь. Порядок и дата закрепления сохраняются.

### Изменение вне CryptoBook

Если файл отсутствует:

- ссылка остаётся в списке, но отображается как недоступная;
- попытка открытия не затрагивает текущий документ;
- пользователь может открепить ссылку или указать новое расположение;
- приложение не должно автоматически удалять пользовательское закрепление.

## 8. Состояние редактора и ограничения

При возвращении к закреплённому файлу он заново загружается с диска. Поэтому в первой версии не сохраняются:

- undo/redo-история;
- текущее выделение;
- положение каретки;
- положение прокрутки;
- открытый режим предпросмотра.

Это осознанное отличие от настоящих вкладок и нескольких сессий.

В последующей версии можно сохранять безопасные навигационные метаданные: позицию каретки, прокрутку и режим просмотра. Сохранение полной undo-истории не требуется.

## 9. Recovery

Многосессионный recovery не нужен, поскольку изменяться может только активный документ.

- Текущий recovery-снимок продолжает защищать активный грязный документ.
- После успешного сохранения перед переключением его снимок удаляется.
- После загрузки нового документа recovery начинает отслеживать новую активную сессию.
- При отменённом переключении recovery текущего документа продолжает работать без переинициализации.

## 10. Ошибки и уведомления

Пользователь получает понятное сообщение, если:

- файл отсутствует или недоступен;
- сохранение текущего документа завершилось ошибкой;
- Save As был отменён;
- формат не поддерживается внутренним редактором;
- расшифровка не удалась;
- введён неверный ключ;
- подготовленное содержимое невозможно загрузить.

Отмена пользователем не должна отображаться как ошибка.

Внутренние исключения журналируются, но технический текст исключения не подменяет локализованное пользовательское сообщение.

## 11. Локализация и темы

- Все новые подписи, подсказки, контекстные команды и сообщения добавляются во все поддерживаемые ресурсы локализации.
- Состояния normal, hover, pressed, selected, disabled и missing используют семантические ресурсы темы.
- Раздел проверяется в Light, Dark, Sepia и System.
- Имя и путь должны корректно обрезаться многоточием и иметь tooltip с полным значением.

## 12. Критерии приёмки

Функция считается готовой, когда выполняются следующие условия:

1. Пользователь может закрепить сохранённый документ и увидеть его после перезапуска приложения.
2. Повторное закрепление того же пути не создаёт дубликат.
3. Нажатие текущего файла не вызывает сохранение или перезагрузку.
4. Грязный документ успешно сохраняется перед переходом.
5. Чистый документ не записывается повторно.
6. Отмена Save As оставляет текущий документ открытым.
7. Ошибка сохранения блокирует переход.
8. Ошибка, отмена или неверный ключ нового файла не изменяют текущий документ.
9. После успешного переключения путь, формат, заголовок и dirty-state соответствуют новому файлу.
10. Переименование внутри CryptoBook обновляет закреплённую ссылку.
11. Отсутствующий файл отображается как недоступный и не удаляется автоматически.
12. Открепление не удаляет сам файл.
13. Быстрые повторные нажатия не запускают конкурирующие операции.
14. Закреплённые защищённые файлы не оставляют постоянных расшифрованных данных.
15. Проводник, workspace-поиск, Open и Quick Access используют одинаковую защиту от потери изменений.

## 13. Тестовые сценарии

Минимальный набор автоматизированных тестов:

- чтение, запись, версия и повреждение JSON-хранилища;
- нормализация путей и устранение дубликатов;
- закрепление, открепление и изменение порядка;
- переключение из чистого и грязного документа;
- Save As для нового документа;
- отмена и ошибка сохранения;
- отсутствующий или заблокированный целевой файл;
- ошибка загрузки после успешного сохранения;
- переключение между обычным и защищённым документом;
- переключение между защищёнными файлами с разными паролями;
- обновление ссылки после переименования;
- отсутствие гонки при двух быстрых командах;
- корректное обновление `DocumentSession`, заголовка и recovery;
- проверка XAML-конструкции `SideMenu` и визуальных состояний всех тем.

Дополнительно требуется ручной smoke-тест реального WPF-приложения: закрепить несколько файлов разных форматов, переключаться между ними, перезапустить приложение, переименовать и удалить один из файлов.

## 14. Не входит в первую версию

- несколько `Home`;
- вкладки документов;
- несколько одновременно загруженных `FlowDocument`;
- отдельные undo/redo-истории для закреплённых файлов;
- фоновое удержание расшифрованного содержимого;
- синхронизация закреплений между устройствами;
- автоматическое закрепление каждого открытого файла;
- полнотекстовый индекс содержимого.

## 15. Рекомендуемый порядок реализации

1. Ввести единый координатор безопасного переключения и перевести на него существующие способы открытия.
2. Добавить тесты транзакционного сохранения и загрузки, включая защищённые файлы.
3. Реализовать версионируемое хранилище закреплённых путей.
4. Добавить ViewModel и раздел «Закреплённые» в `SideMenu`.
5. Связать закрепления с сохранением нового документа и переименованием.
6. Добавить missing-state, контекстные команды и изменение порядка.
7. Выполнить локализацию, тематические проверки и WPF smoke-тест.
