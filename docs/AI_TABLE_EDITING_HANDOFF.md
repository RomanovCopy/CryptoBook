## Статус и разрешённый объём

- Обсуждалась идея, пользователь изначально попросил **«без кода»**.
- Последний запрос — подготовить выжимку для старта в новом чате. Код приложения не менялся, реализация не начиналась.
- Этот файл описывает контекст и возможное решение, а не выдаёт разрешение на реализацию. В новом чате учитывать фактический запрос пользователя.
- Сборка, тесты и интерактивная проверка обсуждаемого сценария не запускались. Возможности оценены по исходникам и документации WPF.

## Потребность пользователя

1. AI-помощник выдаёт оформленный Markdown. Пользователь хочет переносить оформленный результат в основной документ и сохранять его.
2. Главная тревога — возможность **последующего редактирования**, а не только отображения.
3. Пользователь конкретизировал необходимый минимум для таблиц, похожих по работе на Excel:
   - редактирование содержимого ячеек;
   - добавление и удаление строк;
   - добавление и удаление столбцов.
4. Полный функционал Excel не требуется. Формулы, вычисления и сортировка не запрошены.

Пример целевого сценария: AI создал таблицу «Название — Стоимость»; пользователь исправил значения, добавил «Комментарий», удалил строку, сохранил документ и после открытия продолжил редактировать таблицу.

## Что установлено по коду

Все пути ниже указаны относительно корня репозитория.

### Отображение AI и вставка в документ сейчас разделены

- `CryptoBook/AI/AiChatDocumentRenderer.cs`: `Render` использует `MarkdownFlowDocumentRenderer` для получения `FlowDocument`, затем применяет оформление чата.
- `CryptoBook/Behaviors/AiChatMarkdownBehavior.cs`: отображение Markdown в чате; есть обработка обновляемого ответа.
- `CryptoBook/MyControls/AiAssistantPanel.xaml`: команды вставки ответа, замены выделения и копирования.
- `CryptoBook/AI/AiAssistantViewModel.cs`: `Apply` передаёт `lastResponse.Content` в `AiEditorContext`.
- `CryptoBook/AI/AiEditorContext.cs`: в ветке основного RichTextBox вставка сейчас выполняется через **`target.Text = answer`**. Поэтому Markdown вставляется строкой, без структуры и оформления чата.
- В `AiEditorContext.Capture` уже есть проверки актуальности документа, ревизии, выделения и доступности редактирования, а также `BeginChange`/`EndChange`. Их необходимо сохранить при будущих изменениях.

### Готовая основа преобразования

- `CryptoBook/Services/MarkdownFlowDocumentRenderer.cs` — односторонний преобразователь Markdown → FlowDocument.
- Использует Markdig, `UseAdvancedExtensions()` и `DisableHtml()`.
- Поддерживает заголовки, абзацы, выделения, списки, цитаты, разделители, код, таблицы и ограниченный набор ссылок/изображений.
- `RenderTable` создаёт настоящие WPF `Table`, `TableRowGroup`, `TableRow`, `TableCell`; содержимое ячеек — блоки FlowDocument. Это не изображение и не отдельные TextBox.
- Важно: `RenderTable` переносит `ColumnSpan`/`RowSpan`, поэтому предполагать, что любые существующие таблицы прямоугольные без объединений, нельзя.
- `RenderCodeBlock` создаёт оформленный `Paragraph` с подписью языка и текстом кода.
- В чате рендерер вызывается без каталога исходника: изображения не должны читать локальные файлы или загружаться из сети. Существующие ограничения ссылок и HTML следует сохранить.

### Основной документ и формат сохранения

- `CryptoBook/Services/RichTextBoxService.cs` — основной редактор, реализующий `IRichTextBoxService`.
- **Особенность клавиатуры проекта:** Enter вызывает `EditingCommands.EnterLineBreak`, Ctrl+Enter — `EditingCommands.EnterParagraphBreak`. Не подменять это привычным поведением Word/Excel без оценки связанных сценариев.
- `CryptoBook/Services/XamlPackageDocumentFormatHandler.cs` обрабатывает `XamlPackageFileTemplate` и `SecureFileTemplate`; формат содержимого — `DataFormats.XamlPackage`.
- `CryptoBook/Services/TextRangeDocumentFormatHandler.cs` выполняет сериализацию/загрузку через `TextRange`.
- `CryptoBook/Services/XamlPackageDocumentAppearanceCodec.cs` сохраняет дополнительные свойства документа.
- `CryptoBook/Services/FlowDocumentSaveService.cs` — существующий путь сохранения; его надо использовать, сохраняя меры защиты данных.
- Сохранение/повторное открытие именно редактируемых таблиц после доработки ещё предстоит проверить. TXT оформление не сохраняет; равную точность всех экспортных форматов обещать нельзя.

### Отдельный редактор Markdown: не нарушить его контракт

Прочитать `docs/MARKDOWN.md` перед изменениями.

- `.md` редактируется на странице `MarkdownEditor` через TextBox и `IMarkdownDocumentState`.
- Источник истины — Markdown-строка. Просмотр строит новый FlowDocument и доступен только для чтения.
- Обратной конвертации FlowDocument → Markdown нет. Сохранение оформленного документа как Markdown намеренно недоступно.
- Home и MarkdownEditor могут одновременно содержать разные документы, с отдельными состояниями и ревизиями.
- Для основного оформленного документа обсуждался подход: один раз преобразовать ответ AI, затем редактировать и сохранять FlowDocument. Не перестраивать этот фрагмент из первоначального ответа AI после ручных правок: они могут потеряться.
- Это предложенный подход, двустороннее редактирование Markdown пользователь не запрашивал.

### Уже существующие операции со структурой

- `CryptoBook/Services/FlowDocumentContentService.cs`, `CryptoBook/Interfaces/IFlowDocumentContentService.cs`: есть `AddTable(document, rows, columns)`, создание блоков и удаление элементов. `AddTable` добавляет таблицу в конец документа; это ещё не вставка в текущую позицию курсора.
- `CryptoBook/Services/FlowDocumentMoveService.cs`: перемещение элементов, в том числе строк таблицы, с обработкой контейнеров.
- `CryptoBook/Services/FlowDocumentStructureBuilder.cs`: представление таблиц, групп строк, строк и ячеек в дереве структуры.
- `CryptoBook/ViewModels/DocumentStructureViewModel.cs`: удаление/перемещение через дерево, проверки доступности, восстановление курсора, обновление структуры, dirty/revision и закладок. Там уже есть полезные образцы интеграции.
- `CryptoBook/MyControls/RichTextEditorContextMenu.xaml` и `CryptoBook/ViewModels/RichTextContextMenuViewModel.cs`: существующее контекстное меню редактора.
- Полноценный пользовательский набор команд добавления/удаления строк и столбцов в просмотренной реализации не найден. Не путать операции дерева с готовым табличным редактором.

## Предложенное направление, пока не утверждённая спецификация

- Развивать настоящие таблицы FlowDocument в RichTextBox; на текущий минимум отдельный Excel-компонент, WebView или новые зависимости не выглядят необходимыми.
- Использовать один механизм для таблиц из ответа AI и созданных вручную.
- Текст редактировать непосредственно в ячейках.
- Предложены команды контекстного меню: строка выше/ниже, столбец слева/справа, удалить строку/столбец.
- Предложены Tab/Shift+Tab, изменение ширины столбцов и отмена/повтор структурных операций одним действием. Это пожелания ассистента к удобству, **не отдельные подтверждённые требования пользователя**.
- Предложено начать с прямоугольных таблиц без объединённых ячеек. Для уже существующих сложных таблиц нужно выбрать безопасное поведение, не теряющее данные; не разъединять и не уплощать их молча.
- Не решены: поведение при удалении последней строки/столбца, переход из последней ячейки, интерфейс ручного создания таблицы, оформление новых ячеек и заголовков, управление шириной.
- Точное пиксельное совпадение документа с чатом не обещалось: ширина страницы, тема и шрифт могут отличаться.

## Технические вопросы для начала реализации, если она будет запрошена

1. Повторно проверить Git, инструкции и актуальность перечисленных исходников.
2. Выбрать границы первой итерации: только операции над таблицами или также оформленная вставка ответа AI. Пользовательская потребность охватывает оба направления, но их реализация ещё не согласована отдельным заданием.
3. Отделить прикладные операции над таблицей от UI: сервис для структуры, ViewModel для состояния/команд, Behavior для событий, если нужен. Сохранять компактный code-behind.
4. Определять текущую таблицу/строку/ячейку по курсору или выделению; учитывать потерю фокуса при открытии меню, `IsReadOnly`, смену документа, устаревшие TextPointer.
5. При вставке оформленного ответа создавать независимый фрагмент. Нельзя одновременно присоединять одни и те же элементы FlowDocument к чату и документу. Учесть вставку в середину абзаца/ячейки и замену выделения.
6. Для столбцов согласованно менять ячейки всех строк и определения `Table.Columns`; учитывать, что Markdown-рендерер явно не создаёт определения столбцов, хотя ячейки создаёт.
7. При структурных операциях сохранять текст соседних ячеек, оформление, корректную позицию курсора, dirty/revision и актуальность дерева/закладок.
8. Экспериментально проверить Undo/Redo: наличие `BeginChange`/`EndChange` само по себе не доказывает, что все изменения коллекций и ширины будут корректно отменяться.
9. Сначала обеспечить корректность структуры и сохранения, затем удобство управления; не выдавать одну успешную сборку за проверку редактирования.
