# FileExplorer: пакетное удаление и проверка корзины

3 ноября 2026 года.

## Порядок действий

1. Из выбранных путей исключаются дубликаты и элементы, уже охваченные выбранной
   родительской папкой. Правила имён принадлежат провайдеру: локальные пути и MTP
   сравниваются без учёта регистра, старый Android/ADB-провайдер сохраняет регистр.
2. До удаления подсчитывается объём всего локального набора, включая скрытые файлы
   внутри выбранных папок. Содержимое целей ссылок и точек повторной обработки
   при подсчёте не обходится.
3. Для каждого затронутого тома читаются лимит корзины Windows, запрет её использования
   и уже занятый объём. Сравниваются выбранный объём и **лимит минус занятое место**;
   свободное место корзин разных дисков не объединяется. Учитывается политика
   Windows, ограничивающая размер корзины в процентах тома.
4. Если весь набор помещается, показывается подтверждение перемещения в корзину.
   Если хотя бы на одном томе места недостаточно либо корзина отсутствует/отключена,
   показывается предупреждение о безвозвратном удалении **всего выбранного набора**.
   До согласия ни один объект не перемещается и не удаляется. Отмена или закрытие
   подтверждения сохраняет весь набор на месте.
5. После подтверждения выполняется одна операция Windows Shell на одном STA-потоке
   для всего локального набора. Прогресс отражает завершённые элементы. Затем
   ожидаются сверка каталога, плоский список и отрисовка FileExplorer.

Размер корзины читается из настроек текущего пользователя для GUID тома и политики
Windows; занятый объём — через `SHQueryRecycleBinW`. Настройки корзины не изменяются.
Неизвестный лимит, ошибка чтения размера файлов или недоступность диска останавливают
операцию с сообщением, без предположения о свободной/неограниченной корзине.

## Отмена и ошибки

Уже выполненные элементы учитываются и после отмены. Для безвозвратного удаления
используется отдельный счётчик, чтобы сообщение об отмене не обещало восстановление
из корзины. Ошибка безвозвратного удаления также имеет отдельное сообщение.

Переход из режима корзины в безвозвратное удаление во время нативной операции
не разрешён автоматически. Если после предварительной проверки изменятся файлы,
настройки или доступность диска и возникнет ошибка, операция прекращается с точным
полученным частичным результатом. Уже перемещённые объекты остаются в корзине;
приложение не очищает её старые объекты самостоятельно.

Длинное предупреждение прокручивается. Кнопки согласия и отмены находятся в отдельной
строке и остаются видимыми при минимальном размере окна. Тексты и встроенная статья
`files.manage` обновлены на русском, английском, украинском и немецком языках.

## Скорость

Пакетное удаление 50 одинаковых небольших файлов уже реализованным сервисом,
без параллельного запуска тестов:

| Проход | Отдельный вызов на каждый файл | Один пакет |
| --- | ---: | ---: |
| 1 | 1235,31 мс | 339,18 мс |
| 2 | 1200,28 мс | 354,59 мс |

Среднее время самого удаления: **1217,80 → 346,89 мс**, примерно **в 3,5 раза быстрее**.
Предварительная проверка объёма в этих проходах заняла 10–29 мс на набор; она
измерялась отдельно. Все 200 тестовых файлов после замера восстановлены и
проверены; пользовательские файлы в замер не входили.

Прежняя попарная подготовка 2000 путей занимала **7663 мс**. После замены на индекс
выбранных предков последний контрольный замер дал **10,49 мс**, а 10 000 путей —
**71,90 мс**. Это замеры отдельных частей,
а не обещание такого же коэффициента для всего сценария или любого диска.
