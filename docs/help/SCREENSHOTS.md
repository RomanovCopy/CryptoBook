## Общие параметры паспорта

Каждый ID ниже задаёт сценарий, а не квоту изображений. Суффиксы `-a`, `-b` и далее выделяют необходимые состояния/шаги. Каждый текстовый интерфейс снять отдельно на `en-US`, `ru-RU`, `uk-UA`, `de-DE`; общий исходник допустим только без языковых элементов. Системные диалоги учитывают также язык Windows: несовпадение явно записать, кадр не считать локализованным без решения на тематическом этапе.

Поля, наследуемые каждой строкой:

| Поле | Текущее значение после этапа 3 |
| --- | --- |
| Языки и проверка | Для S02-a/b/c, S04-a/b, S06-a/b — сняты/проверены en-US/ru-RU/uk-UA/de-DE; остальные сценарии не сняты |
| Состояние/данные/повтор | Указаны ниже; для двух образцов точные номера шагов и состояния уже заданы в SAMPLE_SCREENSHOTS |
| Дата фактической съёмки/проверки | Для 28 образцов — 2026-10-29, подробности в паспортах; остальные не выполнялись |
| Исходник | `docs/help/screenshots/raw/<culture>/<shot-id>[-state].png`; 28 файлов образцов существуют |
| Аннотации | Отдельно от raw: `docs/help/screenshots/annotations/<culture>/<shot-id>[-state].json`; паспорт в `screenshots/passports/<culture>/` |
| Подпись/alt | Для образцов содержательно переведены в Markdown; для остальных — рабочая русская подпись в таблице, перевод обязателен при написании |
| Поставка | Итоговые PNG в `docs/help/content/<culture>/images/`, единственный источник для будущих WPF Resource `Help/<culture>/images/`; raw/аннотации/паспорта не упаковываются |

Размеры указаны в DIP при 96 DPI; фактический паспорт сохраняет и DIP, и пиксели, DPI, тему, культуру, версию, HEAD и способ получения. Базовый кадр должен показывать саму команду читаемо. Дополнительные проверки 144 DPI (150%), узкого окна и четырёх тем выполняются на тематических этапах и сводятся на этапе 11.

Профили: `M` — основное окно 1440×960; `E` — FileExplorer 1280×900; `D` — диалог по содержимому до 1000×960; `P` — правая панель крупным фрагментом в M; `S` — системный диалог по фактическому размеру; `H` — справка 1120×780, минимум 720×480 DIP с ограничением рабочей областью. Часть небольших мониторов потребует меньшего окна/крупных фрагментов; не уменьшать целое окно до нечитаемых надписей.

## Демонстрационные данные и безопасность повторения

В последующих этапах создать отдельную рабочую папку демонстрации: обычный документ «План поездки» с абзацами, ссылкой, таблицей 3×3 и вымышленными закладками; Markdown с той же темой; папку `Files` с тремя копиями изображений и текстовыми файлами; отдельные `ConflictSource`/`ConflictTarget`; искусственный двоичный файл. Имена и содержимое примеров локализуются. Для удаления/шифрования/сбоев использовать только отдельные расходные копии. Путь к личной папке, реальное имя пользователя и исходный рабочий стол не должны попадать в кадр.

Для AI — служебный вопрос о вымышленном плане и таблице; модель/vision-проектор выбираются по фактической доступности. Не выдавать подставленный текст ответа за полученный от модели. Пароли/ключи не печатать в материалах и не хранить в паспорте. Снимок с отображённым паролем не нужен.

До съёмки изолировать конфигурацию демонстрационного процесса и проверить все хранилища: обычные `Properties.Settings`, общие AI JSON, палитру, тему, историю/избранное, runtime-профили и recovery/lock. Собственная конфигурация exe не гарантирует изоляцию сервисов с жёстким `%LOCALAPPDATA%/CryptoBook`. Не запускать старую утилиту только ради получения кадров: она пишет в `docs/screenshots`, перезаписывает демонстрационные документы и принудительно завершает процесс. На этапе 2 выбран отдельный тестовый профиль/VM для обычного запуска; условия резервной доработки утилиты с изолированными provider/DI и запретом производственных путей перечислены в SAMPLE_SCREENSHOTS. Подготовка/проверка среды — этап 3; на этапе 2 утилита не менялась и не запускалась.
