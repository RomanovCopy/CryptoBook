Каждая культура запускалась отдельным процессом через App.OnStartup с обычными production ViewModel/представлениями и отдельным adaptive AI-worker. Использованы имеющиеся Qwythos-9B…Q4_K_S.gguf и совместимый единственный mmproj…BF16.gguf из 9.1, только для чтения. Запрошены контекст 4096, лимит ответа 256, температура 0, обычный сбалансированный режим и автоматическая память. Сервер, LM Studio, скачивание новых моделей и измерение производительности не требовались.

Настройки WPF — в памяти; AI-settings/runtime profiles/recovery и прочие хранилища — в отдельном artifacts/hv/<culture>/<run>. TEMP/TMP — `artifacts/stage9_2/tmp`. Вымышленные данные: таблица маршрутов с числами 73/24, короткие TXT/Markdown, 400-байтовый двоичный Sample.bin, пустой/завеликий файл, красный квадрат/синий круг 256×256 и код MOON-73. Маркеры LEFT/TARGET/RIGHT на кадрах — контрольные вымышленные данные, не команды интерфейса.

Системный буфер обмена не читался и не менялся. Только для этого режима ITextClipboardService заменён приёмником в памяти: проверены точный payload и отказ записи. Личная переписка, документы и пароли не использовались.

## Проверенные результаты

1. **Настоящий чат.** Модель выдала запрошенную Markdown-таблицу; отдельный renderer и видимый чат показали таблицу. Следующий запрос без повторения таблицы получил 73 из её строки. Проверены фактический Ctrl+Enter KeyBinding поля и команда Send; физическое нажатие клавиш не заявляется.
2. **Выбор и Copy.** Последний непустой ответ выбрался автоматически. Вопрос/ответ выбирались вручную, Select all/clear меняли счётчик и доступность Copy/Insert/Replace. Следующая генерация сохранила ручные отметки. Одиночный Copy равен исходному Markdown без подписи; несколько сообщений — исходнику с локализованными подписями и разделителями в порядке диалога. Ошибка memory sink отобразилась без потери сообщений.
3. **Шаблоны.** В исходной конфигурации шесть встроенных. Окно действительно создало седьмой пользовательский шаблон, допустило пустую инструкцию, затем сохранило её правку с тем же ID. Пустое и повторяющееся локализованное имя отклонены без замены store. В несохранённом черновике удалены все варианты кроме одного; дальнейшее удаление недоступно. Cancel отбросил правки, создание/удаление и выбор, сохранив JSON байт в байт. Переключение шаблона в панели сохранило загруженную модель, историю, черновик и вложение; выбор пережил повторное чтение store. Финальное сохранённое удаление убрало только изолированный пользовательский шаблон, сохранив веса модели.
4. **Обычный редактор.** Выбрана реальная ранее полученная таблица. Insert поставил оформленную WPF-таблицу после текущего выделения и сохранил TARGET/LEFT/RIGHT; Replace удалил только TARGET. Для обеих команд один Undo вернул исходный текст, один Redo восстановил результат. Ячейка отредактирована независимо от ответа в чате. Проверены перенос нескольких сообщений с подписями, его единый Undo и отказ в режиме чтения. Исходный файл на диске не записывался незаметно.
5. **Markdown.** Документ выбран уже после ответа, то есть проверялась текущая цель применения. Preview запретил обе команды с правильным пояснением. В источнике Insert/Replace дали точное ожидаемое строковое содержимое, один Undo/Redo вернул/повторил целую операцию. Несколько сообщений вставились как точный payload Copy и отменились одним действием. Возврат Home сохранил независимый обычный документ.
6. **Снимки документов.** Current document взял весь обычный текст вне текущего выделения, включая крайний маркер. Правка документа после прикрепления не изменила карточку. Отдельно проверен весь Markdown-исходник с разметкой и неизменность снимка после дальнейшей правки источника.
7. **Файлы и ошибки.** Реальные readers извлекли TXT и только первые 256 байт HEX из 400-байтового binary; смещение 0xF0 присутствует, 0x100 не передаётся. Настоящий FileDropCommandBehavior получил routed Drop с расходным путём и добавил карточку через общий production command. Пять файлов в одной партии оставили четыре принятые карточки и точное сообщение лимита; файл 32 МиБ + 1 байт и пустой TXT отклонены.
8. **Настоящий mixed vision.** Отправлены отдельные PNG и снимок документа с MOON-73. До отправки живой документ изменён на CHANGED-94. Модель назвала красный и синий цвета и исходный код 73; запрос не содержал числа 73. Следующий вопрос получил этот код снова, отправленные карточки остались в истории. Ответы не подменялись fixtures или заранее написанными сообщениями.
9. **Новый чат.** Удалил историю, черновик, pending-вложение и отметки; веса остались загруженными. Явная выгрузка завершила проверку.

По **60 проверок на культуру**, включая две общие проверки изолированного Save и отсутствия binding errors; итого **240**, binding errors=0. Последний прогон ограничивал замену PNG фильтром S40-b,S42-a, но выполнял все сценарии целиком. Отчёты `screenshots/validation/stage9_2/scenarios-<culture>.json`; реальные вымышленные ответы — `ai-<culture>.json`.

## Съёмка и исправления

Сняты настоящие видимые WPF-представления через RenderTargetBitmap при 96 DPI. Главное окно 1440×960 DIP; панель 550×930; настройки увеличены до 740×1000 DIP, чтобы поля шаблона и Save/Cancel помещались вместе. Снимки не содержат дорисованных элементов или ответов. Все 60 кадров и 16 контактных листов просмотрены; паспорта помечены Reviewed.

В первых вариантах номера соседних иконок перекрывали друг друга, а состояние выбора сохраняло тестовую ошибку Copy. Эти варианты отклонены: пометки перенесены над кнопками, функциональная проверка отказа Copy выполняется после кадра нормального выбора. S40-b/S42-a пересняты на всех языках. Предварительные настройки с прокруткой заменены более высоким настоящим окном; поля, ошибка и Save/Cancel видны полностью. Контактные листы обновлены после последней съёмки.

Исправлена неточная production-подсказка **AI.RemoveAttachment**: она называла любой файл «приложенным текстом». Теперь на четырёх языках это «вложение» / attachment / Anhang. Ключ и поведение удаления сохранены. Иных изменений логики продукта не потребовалось.

В статьях явно описаны границы Markdown-вставки: передаётся точный исходник без автоматических переносов строк, поэтому для самостоятельных таблиц/заголовков нужно подготовить границы блока. Контрольный S43-d специально сохраняет текст вокруг точки вставки; он не выдаётся за готовую отдельную таблицу в preview. AI_TABLE_EDITING уточнён тем же правилом и актуальным названием **Вставить выбранное**.

Обновлены catalogue/locale/FEATURES/TOPICS/SCREENSHOTS/PROGRESS и число встроенных статей в HelpTests. Planned-навигация теперь проверяется на `ai.context`, поскольку `ai.chat` доступен. Режимы 9.1 и прежние кадры сохранены.
