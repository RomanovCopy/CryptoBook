## Условия написания

- Две образцовые статьи: `start.interface` и `doc.create` (со ссылкой на зарегистрированную плановую `doc.save`). Четыре языковые версии и 28 снимков подключены в работающем окне на этапе 3; методы проверки — [VALIDATION_STAGE3.md](VALIDATION_STAGE3.md).
- `help.use` — запланированная статья, команды F155–F158 уже существуют: меню/F1, поиск, история, увеличение изображений, одно окно. Перенос старой справки Markdown завершается на этапе 5 после сохранения всех примеров; подробная статья о самой справке — этап 10.
- «Формат листа» и «Ориентация» подтверждены в диалоге создания. Отдельную команду изменения этих параметров для уже открытого документа не обещать без проверки.
- Таблицы: пользовательский вход — существующая таблица, в том числе вставленная из AI; отдельная команда создания пустой таблицы не обнаружена.
- Не превращать технические типы Run/Span, worker или параметры запуска разработчика в обязательные шаги обычного пользователя. Их пользовательские последствия объяснять простыми словами.
- Каждую строку реестра функций связывать с этой таблицей. Если при живой проверке найдётся новая команда, сначала добавить запись в реестр и соответствующую тему, затем писать статью.
