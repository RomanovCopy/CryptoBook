## 1. Окно и входы

Обязательные свойства: отдельное окно, оглавление слева, статья справа, весь комплект на языке приложения, работа без сети. Выбранные дополнения:

| Свойство | Решение и граница |
| --- | --- |
| Открытие | Новый пункт «Справка» верхнего уровня бокового меню, после существующих групп. Не менять выбранную страницу основного окна |
| Немодальность | Открывать через `IWindowManager.ShowWindow`; основное окно остаётся доступным. Владелец — главное окно, а не случайное активное вспомогательное окно |
| Один экземпляр | Один на процесс. Повторный вызов восстанавливает свёрнутое окно и активирует существующее; после закрытия создаётся новое |
| F1 | В основном окне и в самой справке. Обычный вызов открывает последнюю тему, при первом открытии — `start.interface`; в справке F1 только активирует окно. В модальных диалогах и стороннем видеоплеере F1 на этом этапе не обещается |
| Контекстный вход | Кнопка существующей справки Markdown открывает `md.syntax`, не переключая основной Frame. Пока тема не написана, действует переходный порядок раздела 7 |
| Навигация | Дерево разделов, поиск, «Назад»/«Вперёд», изменяемая ширина двух панелей |
| Состояние | Последняя тема, геометрия нормального окна и ширина левой панели сохраняются. Запрос и история переходов живут только до закрытия окна |
| Изображения | Вписать по ширине статьи без растяжения сверх исходного размера; щелчок/Enter открывает увеличенный просмотр в этом же окне, Esc возвращает к месту чтения |

Не включать контекстную привязку F1 к каждому контролу, избранные статьи, сетевой контент, вкладки и печать справки в минимальную реализацию этапа 3. Они не нужны для обязательного сценария.

Окно не вызывает сохранение/закрытие документов, навигацию основного Frame, выгрузку модели, очистку чата или изменение выделения редактора. Чтение справки доступно и при заблокированном рабочем пространстве; оно не даёт команд разблокировки и не содержит пользовательских данных.

## 2. Компоновка, размер и клавиатура

Эскиз описывает расположение, а не изображает существующий интерфейс:

```text
┌ CryptoBook — Справка ────────────────────────────────────┐
│ Назад   Вперёд   Оглавление                              │
├──────────────────────┬─┬────────────────────────────────┤
│ Поиск по справке [ × ]│ │ Заголовок статьи               │
│ Оглавление / Найдено  │ │ Вводный текст                  │
│ ▾ Начало работы      │ │ Шаги, снимки, подписи          │
│   Основные области…  │ │                                │
│ ▾ Документы          │ │ Связанные темы                 │
│   Создать и сохранить│ │                                │
└──────────────────────┴─┴────────────────────────────────┘
```

- Начальный размер 1120×780 DIP, минимальный 720×480 DIP. Левая панель по умолчанию 280 DIP, диапазон 220–420 DIP, правая не уже 360 DIP. Разделитель ограничивает ширину с учётом текущего окна; сохранённое значение также ограничивается при восстановлении.
- При узком окне сохраняются две панели. Заголовки и кнопки переносятся по строкам; длинное название темы допускает сокращение с полной подсказкой/доступным именем. Статья прокручивается вертикально. Таблица или крупный снимок получает собственную горизонтальную прокрутку/увеличение, а не расширяет всё окно.
- Если рабочая область монитора меньше минимума из-за DPI, фактический размер и минимум ограничиваются рабочей областью. После отключения монитора окно помещается в доступную рабочую область; исходно — по центру владельца. Не восстанавливать свёрнутое состояние.
- Tab/Shift+Tab: навигация → поиск/очистка → дерево или результаты → статья/ссылки. В дереве стандартные стрелки и Enter; Enter в результатах открывает выбранное. Все кнопки имеют локализованные имена и видимый фокус.
- Ctrl+F переводит фокус в поиск справки; Alt+←/→ — история справки. Эти клавиши работают только при фокусе справки. Esc сначала закрывает увеличенное изображение; в поле поиска очищает непустой запрос, затем возвращает фокус в статью; в остальных местах не закрывает окно. Alt+F4 закрывает справку.
- Смена темы оформления использует существующие DynamicResource. Цвета текста документа не участвуют. Проверить Light, Dark, System, Sepia, 96/144 DPI и длинные немецкие подписи.

## 3. Темы, история и поиск

Единица навигации — постоянный ID вида `doc.create`, а не заголовок/путь файла. Выбор темы синхронизирует дерево и статью. Разделы группируют темы, но сами не являются пустыми статьями. Порядок разделов/тем — порядок массивов в `content/catalog.json`.

История хранит последовательность ID и позиции вертикальной прокрутки. Первый успешный показ создаёт начальную запись; переход в другую доступную тему добавляет запись, очищая ветвь «Вперёд». Повторный выбор той же темы не добавляет дубликат. «Назад»/«Вперёд» восстанавливают тему и её позицию. Смена языка сохраняет ID/индекс истории, но сбрасывает все позиции прокрутки: длина переводов разная. Последняя тема обновляется только после успешного открытия доступной статьи. Недоступная ссылка/ошибка загрузки не портит текущую статью и историю.

Поиск локальный, только по поставляемым доступным статьям текущего языка: заголовок H1, `keywords` и видимый текст Markdown, включая подписи/alt. Синтаксис разметки, адреса ссылок, ID и служебные JSON не индексируются. Регистр не учитывается согласно текущей культуре; Unicode нормализуется в Form C. Начальные/конечные пробелы удаляются, повторные пробелы разделяют слова. Все слова должны встречаться в индексируемом тексте; поиск по подстроке, без морфологии, исправления ошибок и перевода.

Порядок результатов: все слова в заголовке → все слова в заголовке/ключевых словах → остальные совпадения в тексте; внутри группы — порядок каталога. Результат содержит локализованный заголовок и короткий фрагмент с совпадением. Задержка после ввода 200 мс; Enter выполняет немедленно и открывает выделенный результат при наличии. Размер запроса ограничить 200 символами.

Пустой запрос показывает дерево. Непустой заменяет дерево списком результатов в той же левой панели; текущая статья справа остаётся. «Оглавление» и очистка запроса возвращают дерево с выделенной текущей темой. При отсутствии совпадений показывается локализованное сообщение; текущая статья не исчезает. Выбор результата оставляет запрос и список, чтобы можно было прочитать соседнее совпадение.

## 4. Язык и неполный комплект

Список культур берётся из `LocalizationManager.AvailableLanguages`: `en-US`, `ru-RU`, `uk-UA`, `de-DE`. Изменение этого списка требует расширить весь комплект справки. Самостоятельного переключателя языка в окне нет.

На `CultureChanged` отменить отложенный поиск, убрать старые результаты, очистить запрос, заменить дерево, навигационные подписи, статью, alt/подписи и изображения одной сменой состояния. Текущий ID, история и раскрытие общих разделов сохраняются, фокус остаётся в той же области. Индекс строится заново для новой культуры. Поколение запроса/культуры не позволяет запоздалому результату вернуть старый язык.

Нет автоматической подстановки чужого языка. Если файл текущей локали повреждён/потерян, показать сообщение на текущем языке с безопасным возвратом к оглавлению; исходную статью на другом языке не оставлять. При отсутствии локализованной цели в истории запись остаётся на своём месте и показывает состояние недоступности, без записи нового перехода. Повторная смена языка позволяет открыть тот же ID.

В процессе разработки каталог содержит `planned`, `sample`, впоследствии `ready`. В дерево и поиск попадают только темы, имеющие файлы на всех поддерживаемых языках (`sample` или `ready`). Незавершённые разделы скрываются. Ссылка на зарегистрированную `planned`-тему показывается текстом с локализованным пояснением «Статья ещё готовится» и не переходит в пустую страницу. Неизвестный ID — ошибка проверки, а не допустимая заглушка. На этапе 12 все 76 тем и их иллюстрации должны пройти проверку и стать `ready`.

Для этапа 3 доступны две образцовые темы. `doc.save` остаётся зарегистрированной целью этапа 4: шаг сохранения есть в `doc.create`, но отдельной полной статьи пока нет. Это явная отложенная связь, не утверждение готовности статьи.

## 5. Один источник текстов и формат

Принятое размещение: `docs/help/content/`. Оно пригодно для редактирования до реализации и затем включается в приложение; копию Markdown в `CryptoBook/` не создавать. `TOPICS.md` остаётся редакционной матрицей содержания/этапов, `FEATURES.md` — реестром функций. Машинный каталог проверяется на совпадение ID с этой матрицей.

| Путь относительно `content/` | Назначение |
| --- | --- |
| `catalog.json` | `schemaVersion=1`, культуры, упорядоченные разделы, все 76 ID со статусами/разделом; у образцов также `featureIds` и `illustrationIds`; реестр плановых иллюстраций |
| `<culture>/locale.json` | `culture`, переведённые названия всех разделов, `topics` с `id`, `file`, массивом `keywords` для существующих текстов |
| `<culture>/<topic-id>.md` | Единственный текст статьи; один H1 задаёт её заголовок в дереве/поиске. Никакого YAML, HTML или исполняемых вставок |
| `<culture>/images/<shot-id>.png` | Подготовленная иллюстрация для поставки. На этапе 2 файлов изображений ещё нет |

Порядок полей JSON незначим, порядок массивов значим. `status` принимает только `planned`, `sample`, `ready`. `file` — относительное имя `<id>.md`; `featureIds` ссылаются на Fxxx; `illustrationIds` — на реестр `illustrations` общего каталога. Иллюстрация имеет `id`, `scenarioId`, `status` (`planned`/`ready`) и относительный `file`. Статус `ready` у неё означает наличие проверенных вариантов всех культур. Текущий каталог является конкретным образцом схемы; не создавать второй каталог с дублирующим содержимым.

Поддерживаемая разметка: H1–H3, абзацы, жирный/курсив, простые списки, цитата-предупреждение, таблицы, inline-code для имён/клавиш/синтаксиса, блоки примеров синтаксиса Markdown. Программирование не является пользовательским действием. Общий [шаблон](ARTICLE_TEMPLATE.md) обязателен для практических статей; обзор может сократить неуместные разделы.

Ссылки между статьями: `[локализованное название](help:doc.save)`. На первом этапе нет внутристатейных якорей, поэтому переименование заголовка не ломает адрес. Набор ссылок в четырёх переводах совпадает. Кликабельные внешние ссылки в минимальном комплекте не нужны; адреса при необходимости показываются обычным текстом, а не запускают приложение.

Изображение: стандартная Markdown-запись с относительным `images/S04-a.png`, локализованным alt и непустым title-подписью. Подпись рендерится отдельной строкой, alt доступен средствам чтения. Имя файла и ID кадра одинаковы во всех культурах; содержимое переводится. На этапе 2 ссылка на отсутствующее изображение допускается только при его явном `planned` в каталоге и в [плане кадров](SAMPLE_SCREENSHOTS.md). В этапе 3 все семь состояний образцов должны существовать на четырёх языках; плановая декларация не заменяет снимок.

## 6. Рендеринг, изображения и поставка

Использовать текущий Markdig `1.3.2` и WPF FlowDocument. Новые пакеты, WebView/браузер и сетевой перевод не нужны. Текущий `MarkdownFlowDocumentRenderer` уже разбирает Markdown, отключает активный HTML и создаёт WPF-элементы; **сейчас он не поддерживает** `help:` и изображения из ресурсов. В этапе 3 добавить явную политику разрешения ссылок/изображений для справки с прежними ограничениями по умолчанию у пользовательского Markdown/AI. Не пропускать `help:` через внешний обработчик URL и не ослаблять правила пользовательских файлов.

На этапе 3 подключить файлы из единственного `docs/help/content/` как WPF `Resource` с логическими путями `Help/catalog.json`, `Help/<culture>/locale.json`, `Help/<culture>/<id>.md`, `Help/<culture>/images/<id>.png`. Разрешение через ресурсы сборки CryptoBook, например `pack://application:,,,/CryptoBook;component/Help/ru-RU/doc.create.md`; нормализация регистра ресурса проверяется по реально собранному перечню. Не полагаться на `Environment.CurrentDirectory`, исходный репозиторий или файлы рядом с exe. Это подходит существующему `PublishSingleFile=true`, но фактическая проверка публикации обязательна.

Разрешать только темы и ресурсы из каталога текущей культуры. Отклонять абсолютные файловые пути, UNC, `..`, обратные разделители, URI к другой сборке, сеть, схемы запуска и обход ограничений через percent-encoding. Внешний ввод не формирует произвольный pack URI. HTML/XAML из статей не исполнять. Повреждённый JSON/изображение даёт локализованное состояние ошибки, без загрузки из другого места.

Для PNG сохранить текущие пределы: не более 25 МиБ на файл, декодирование до 1600 пикселей по ширине; увеличенный просмотр использует тот же предел и прокрутку, без требования скачивания/сохранения. Крупный экран сопровождать отдельным фрагментом. Базовые 1440×960 кадры не теряют читаемость из-за ограничения. Общие изображения разрешены лишь без языкового текста и при явном указании в каталоге; у образцов все кадры языковые.

Исходники кадров хранятся в `docs/help/screenshots/raw/<culture>/`, отдельные номера/рамки — в `docs/help/screenshots/annotations/<culture>/<shot-id>.json`. В поставку входит только PNG, составленный из raw и аннотаций. Его не редактировать независимо от исходников. Текстовая подпись и alt остаются только в статье. Паспорт/координаты описаны в [плане образцов](SAMPLE_SCREENSHOTS.md); этот файл и raw не упаковывать в приложение.

## 7. Существующая MarkdownSyntaxHelp

Не терять текущую краткую справку до переноса её примеров. Переходный порядок:

1. В этапе 3 сохранить страницу и её текущие локализованные примеры, кнопку входа/возврата и Esc. Добавить в неё локализованный переход к новому окну, теме `start.interface`. `md.syntax` пока `planned`, поэтому нельзя отправить пользователя в отсутствующую статью или удалить прежний полезный материал.
2. В этапе 5 перенести все группы `MarkdownSyntaxHelpViewModel` в `md.syntax`/`md.edit`/`md.preview` на четырёх языках; проверить сохранение примеров по перечню текущих групп. После этого `OpenSyntaxHelp` непосредственно открывает отдельное окно на `md.syntax`, не вызывая навигацию основного Frame.
3. Тогда удалить старую страницу, ViewModel, интерфейс, DI/маршрут и неиспользуемые ключи после проверки ссылок/тестов. Не поддерживать два расходящихся текста синтаксиса. «Назад» в новой справке относится только к её истории; возвращение к редактору — активация основного окна или закрытие справки.

Так этап 3 не требует внепланово писать всю статью о Markdown, а этап 5 заканчивает единый путь входа.

## 8. Сохранение состояния и разделение ответственности

`HelpWindowService` управляет одним окном через существующий `IWindowManager`; при необходимости расширить API явным владельцем, не менять владельцев остальных окон. ViewModel хранит выбранный ID, дерево/результаты, историю, запрос и локализованные состояния. Сервис содержания проверяет каталог и загружает ресурсы. Рендерер отвечает за FlowDocument и разрешённые переходы; Behavior — только за фокус/прокрутку/клавиатуру, если обычных привязок недостаточно. Регистрации — в Autofac Startup, code-behind минимальный.

На этапе 3 добавить совместимые пользовательские настройки `HelpLastTopicId`, `HelpWindowLeft/Top/Width/Height`, `HelpNavigationWidth` с начальными значениями; для отсутствующей/удалённой темы — `start.interface`, для невалидной геометрии — размер по умолчанию. Не хранить запросы/тексты статей/историю на диске. Настройки записываются при нормальном закрытии справки; отказ записи не блокирует чтение. Освобождать события культуры/темы и отложенный поиск при закрытии, не накапливая обработчики после повторных открытий.
