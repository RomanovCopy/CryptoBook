изолированными сервисами и настройками в памяти, затем завершает свой процесс
до обычного запуска с профилем пользователя. Это инструментированный запуск
поставки, не запуск установленного рабочего профиля без подмен.

Проверено, что entry assembly — CryptoBook, а CryptoBook.dll загружен из
уникальной распаковки **этого EXE**, не из bin проверочного инструмента.

`948D8992E973257707296F77F80DF469BC500054B2B2E710BED5BD065EB55E15`.
Проверочный инструмент поставляется этому запуску одним DLL; зависимости
приложения и весь `Help/` берутся из single-file bundle.

## Найденные ошибки и неуспешные попытки

- Тест `DocumentBackgroundPreferenceTests` сохранял реальные настройки тестового
  профиля и получил отказ доступа. Переведён на `MemorySettingsProvider` и общую
  непараллельную коллекцию Settings UI; production-поведение не менялось.
- `CONTRIBUTING.md` предлагал прямой `dotnet test`, расходящийся со штатной
  изоляцией WPF/xUnit. Команда заменена на `Run-ReleaseTests.ps1`.
- Устаревшие текущие статусы TOPICS/FEATURES/SCREENSHOTS/PROGRESS приведены к
  завершению плана. Исторические отчёты не переписаны в успешную аппаратную приёмку.
- Первый sandbox-прогон имел шесть ошибок: две проверки PID cleanup, доступ к
  настройкам, IPC и две проверки корзины Windows. После исправления изоляции
  настроек штатный прогон с доступом к нужным функциям Windows дал 1208/1208.
  Первый `restore` в sandbox завершился с кодом 1 без вывода; повтор с обычным
  доступом прошёл в locked-mode. Первые результаты не включены в успешные.
- Первый package startup hook выполнил проверки, но `Environment.Exit` из
  startup hook вызвал assertion CLR при завершении WPF. Такой запуск не принят.
  Проверочный hook теперь после нормального `App.Run`/OnExit и закрытия файлов
  завершает только собственный процесс через Win32 с итоговым кодом. Четыре
  финальных запуска завершились с кодом 0; одного сообщения PASS недостаточно.
- При перекрытии дополнительного `verify` и другого WPF-прогона uk-UA один раз
  не прошёл общую проверку сохранности. Добавлена поэлементная диагностика;
  дальнейшие WPF-проверки выполнены последовательно. После завершения соседней
  сессии диагностический повтор и три финальных uk-UA-прохода сохранили все поля.
  Сбой не воспроизведён; конкретное отличавшееся поле первой попытки неизвестно.
  Прямых свидетельств потери данных или ошибки production-кода нет. Первая
  попытка сохранена в `stage12/scenarios` вне репозитория и не считается PASS.
