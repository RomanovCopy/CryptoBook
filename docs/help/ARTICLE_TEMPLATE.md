# Шаблон статьи встроенной справки

Принят на этапе 2. Правила хранения, ссылок и рендеринга — в [спецификации](SPECIFICATION.md). Рабочие образцы и матрица — в [SAMPLES.md](SAMPLES.md).

## Редакционный порядок

1. Зарегистрировать постоянный ID/раздел в `content/catalog.json` и связать его с Fxxx в FEATURES и этапом в TOPICS. Не переводить ID.
2. Создать ровно один `<culture>/<id>.md` для каждой культуры каталога. Заголовок H1 — единственный источник названия темы; добавить `id`, `file`, содержательные `keywords` в соответствующий `locale.json`. Ключевые слова переводить, а не копировать между локалями.
3. Записать UI-термины и их ключи в паспорт проверки, сверить четыре `Resources*.resx`. В шагах писать видимые названия элементов, не имена методов/ключей. Не улучшать перевод кнопки только в статье: сначала согласовать исправление самого UI на соответствующем этапе.
4. Планировать изображения по шагам; в `catalog.json` зарегистрировать ID/путь/статус, в SCREENSHOTS — сценарий и паспорт. Каждая статья содержит свои локализованные alt и title-подпись. Номера на снимке соответствуют шагам; для обзорной статьи — номерам областей.
5. Проверить одинаковый смысл действий, предупреждений, результата и возврата во всех языках. Заполнить пять независимых отметок: текст, UI-термины, ссылки, изображения, живой сценарий. Не менять `sample` на `ready`, пока обязательные отметки не закрыты на всех языках.

## Копируемая структура практической статьи

Ниже редакционные заполнители; этот шаблон не включается в поставку и не является отдельной темой. Разделы и служебные слова переводятся вместе с текстом.

```markdown
# Короткое название задачи

Для чего нужно действие и какой понятный результат получится.

## Перед началом

Нужное состояние, открытый документ/папка, допустимый источник/формат.
Если действие способно удалить/заменить данные — предупреждение до шага.

## Порядок действий

1. Откройте **точное название команды** в **точном разделе**.
2. Выберите один параметр или выполните одно действие.

![Что видно и где нужный элемент](images/S04-a.png "Шаг 2. Короткая подпись к снимку.")

3. Подтвердите действие кнопкой **точная подпись**.

## Проверка результата

Конкретный видимый признак; если нужно — повторное открытие расходного файла.

## Отмена и возврат

Как отменить до подтверждения или вернуться после него.
Не обещать универсальную отмену уже записанного/удалённого файла.

## Если не получилось

Конкретный признак → подходящее действие. Ограничения формата/источника.
Точное сообщение цитировать лишь после сверки с текущим ресурсом/сценарием.

## Связанные темы

- [Понятное название связанной темы](help:doc.save)
```

Обзорная статья может заменить условия/процедуру описанием пронумерованных областей и короткой последовательностью знакомства. Не добавлять пустые разделы ради формального соответствия. Сам текст должен объяснять действие без снимка. Избегать ненужных технических деталей; для Markdown уместны образцы его пользовательского синтаксиса.

## Паспорт проверки вне пользовательского текста

В SAMPLES или тематическом отчёте указывать: ID, культуры, версия/HEAD, Fxxx, Sxx/состояния, ключи терминов, фактическая проверка текста/ссылок, дата и способ съёмки, результат пользовательского сценария и остающиеся условия. Не встраивать служебную матрицу, слова «образец этапа 2», пути исходников и непроверенные обещания в текст, который будет читать пользователь.
