# Локальный AI-помощник

Доступен начиная с CryptoBook 1.1.4.4. GGUF-модели и vision-проекторы не входят в установщик и выбираются пользователем отдельно.

1. Откройте **Настройки → AI-помощник → Настройки модели** либо нажмите **AI** справа в заголовке и **Настройки модели**.
2. Включите помощника, нажмите **Обзор…** и выберите файл языковой модели `.gguf`. Файл проектора `mmproj` выбирать не нужно.
3. При желании нажмите **Проверить модель**, затем **Сохранить**. Дополнительные приложения, сервер и сетевые адреса не требуются.
4. Напишите запрос в правой панели. **Ctrl+Enter** отправляет запрос, **Остановить** прерывает генерацию.

Если **Отправить** недоступна, под полем запроса и в подсказке кнопки указана причина: помощник выключен, сообщение пустое, вложения читаются, выполняется предыдущий запрос или защищённое рабочее пространство заблокировано. Сохранённый зашифрованный снимок для последующего восстановления сам по себе не блокирует обычную работу и отправку новых запросов. При действительной блокировке пространства отправка, вложения и применение ответа недоступны; диалог и черновик очищаются при сбросе ключа.

Ширина панели меняется перетаскиванием её левой границы и сохраняется при закрытии и повторном открытии панели. При уменьшении окна ширина ограничивается доступным местом.

Модель выбирается в окне **Настройки модели**: укажите GGUF-файл или выберите ранее настроенную модель из списка и нажмите **Сохранить**. Параметры каждой модели сохраняются отдельно. Смена модели отменяет текущую генерацию, выгружает прежнюю модель и начинает новый диалог; выбранная модель загружается при следующем запросе.

Нажмите **Прикрепить файлы…** или перетащите файлы в панель. Документы и изображения показаны карточками с именем и размером; у изображений есть миниатюра. Кнопка **Текущий документ** прикладывает весь текст открытого документа как файл-снимок, включая несохранённые изменения. До отправки любое вложение можно убрать. Содержимое фиксируется при прикреплении и сохраняется в памяти диалога для последующих вопросов. Сохранённые изображения повторно включаются в текущий запрос модели при уточняющих вопросах.

Поддерживаются текстовые файлы, Markdown, RTF, DOCX, XamlPackage, PNG, JPEG, BMP, GIF и TIFF. Из документов извлекается текст. Для изображений нужна модель с поддержкой зрения и соответствующий `mmproj*.gguf` в той же папке; при единственном таком файле он подхватывается автоматически. Визуальный модуль работает на процессоре и использует ОЗУ; вручную задавать второй путь не требуется. При неподходящей модели запрос не отправляется, изображение остаётся прикреплённым. Максимум — четыре файла на сообщение, 32 МБ на файл и 500000 символов текста; изображения уменьшаются до 1280 пикселей по большей стороне. Пустой запрос с вложением получает стандартную команду анализа файлов.

Ответ можно скопировать, вставить в позицию курсора открытого редактора либо заменить им исходное выделение. Эти действия применяются к открытому документу в CryptoBook. Вставка в обычный редактор и исходник Markdown поддерживает Ctrl+Z. Если исходный документ изменился после запроса, автоматическое применение блокируется; ответ можно скопировать вручную. В режиме предпросмотра Markdown ответ применяется после перехода в исходник и нового запроса.

Во время распознавания картинки панель показывает **Обработка изображения…**, а при появлении текста — **Генерация ответа…**. Визуальный модуль использует процессор; обработка фотографии может занять заметное время до первого текста.

## Параметры и память

- Контекст и максимальная длина ответа задаются в токенах. Лимит ответа можно задать больше контекста: фактический ответ ограничивается оставшимся местом после запроса и истории. Например, контекст 4096 и лимит ответа 10000 сохраняются и работают вместе. Когда сам запрос с историей не оставляет места для ответа, помощник предлагает очистить диалог или увеличить контекст; сообщения не удаляются незаметно.
- Проверка модели и сохранение используют одинаковые правила проверки исходных параметров. Кнопки сначала принимают последние значения из полей ввода. Ошибки указывают конкретный параметр.
- Креативность: 0–2; меньшее значение даёт более предсказуемый ответ.
- По умолчанию память распределяется автоматически: число слоёв GPU подбирается по бюджету видеопамяти с запасом для контекста и рабочих буферов; остальные слои используют ОЗУ и процессор. При ошибке загрузки весов помощник повторяет загрузку с меньшим числом слоёв GPU, вплоть до CPU. Веса отображаются из файла в память средствами Windows, без обязательного копирования всего файла в ОЗУ.
- Для Gemma 4 E2B/E4B при частичном размещении на GPU автоматически отключается Flash Attention: это обходит аварийное завершение встроенного llama.cpp при подготовке вычислительного графа. Слои GPU продолжают использовать видеокарту; правило действует при проверке модели, в текстовом чате и при работе с изображениями.
- В дополнительных параметрах можно выбрать **Только процессор · ОЗУ** или вручную задать число слоёв GPU: 0 — процессор, -1 — все слои на видеокарте. Там же находятся рассуждения для Qwen/Gemma и инструкция для модели. Большой контекст увеличивает расход памяти; размер файла модели не равен потреблению видеопамяти.
- Параметры сохраняются отдельно для каждого файла. Ранее выбранные модели доступны в списке окна настроек.

Флажок **Разрешить развёрнутые рассуждения** управляет режимом поддерживаемых Qwen/Gemma. Рядом постоянно видно предупреждение: **Не все модели поддерживают отключение рассуждений**. **Проверить модель** использует текущее положение флажка; для применения в чате нажмите **Сохранить**. Для Gemma 4 E2B/E4B при отключении используется обычное начало ответа без пустого канала рассуждений; для старших Gemma 4 сохраняется их собственный формат отключения. Включение добавляет управляющий токен рассуждений. Описание форматов: [Google Gemma — Thinking mode](https://ai.google.dev/gemma/docs/capabilities/thinking).

Если модель выдаёт размеченные рассуждения, они поступают в отдельный сворачиваемый блок **Рассуждения модели** с рамкой и приглушённым цветом, независимо от положения флажка. Пока анализ идёт без итогового ответа, статус показывает **Модель рассуждает…**. Поддерживаются каналы Gemma, блоки `<think>` и канал analysis; учитывается и уже открытый канал в шаблоне запроса. Копирование, вставка и последующая история используют только итоговый ответ. Рассуждения без итогового ответа сохраняются в блоке, а панель поясняет, что можно увеличить лимит ответа. При остановке частичный анализ остаётся доступен; очистка чата и блокировка удаляют его вместе с сообщениями. Рассуждения передаются только в памяти, включая изолированный процесс, и не записываются в настройки или журналы. Для текста и изображений используются одинаковые правила разделения. Если модель выдаёт обычный текст без границ каналов, надёжно отделить анализ от ответа по одним словам нельзя.
- **Выгрузить модель** останавливает текущую генерацию и освобождает веса и контекст. Следующий запрос загружает модель заново.
- По умолчанию модель выгружается после 10 минут бездействия; 0 отключает автовыгрузку. Проверка простоя выполняется каждые 15 секунд. Активная генерация не считается простоем.
- Смена настроек/модели и отключение AI очищают диалог и выгружают модель. Блокировка защищённого рабочего пространства очищает диалог, черновик и приложенный контекст, отменяет генерацию и выгружает модель. При закрытии приложения нативные ресурсы освобождаются.

Обработка выполняется локально через LLamaSharp/llama.cpp с Vulkan и CPU в отдельном процессе того же `CryptoBook.exe`. Сервер и сеть не используются. Модель загружается из выбранного файла и не копируется. Диалог и вложения передаются по каналу в памяти и не сохраняются на диск приложением. Настройки без содержимого документов находятся в `%LOCALAPPDATA%\CryptoBook\ai-settings.json`. Модели не входят в дистрибутив. Поддержка конкретной архитектуры GGUF зависит от встроенного движка; вызов инструментов моделями в этой версии не подключён. Выгрузка освобождает также визуальный модуль; очистка диалога, блокировка и смена модели удаляют вложения из панели и истории.

## Автоматическая проверка и восстановление

Режим **Автоматически** проверяет загрузку модели, создание контекста и короткую генерацию на служебном запросе. При неудаче последовательно отключает Flash Attention, уменьшает пакеты обработки и число слоёв GPU, пробует CPU. Если включено **Разрешать автоматическому режиму уменьшать контекст**, дополнительно проверяет меньший контекст, вплоть до 512 токенов. Заданное пользователем значение контекста сохраняется; фактическое значение и предупреждение о меньшей вместимости истории видны в панели и настройках. История и вложения не обрезаются автоматически. В ручном режиме число слоёв GPU и контекст не подбираются заново.

Первая проверка требует дополнительного времени: чтение метаданных ограничено 60 секундами, каждая пробная генерация — 120 секундами. Проверка конечна (не более 13 вариантов), её можно остановить. Панель **Проверки, изменения параметров и причины сбоев** показывает время, параметры каждой попытки, код аварийного выхода или понятную причину отказа. Основные параметры, переход на CPU, отключение Flash Attention и уменьшение контекста видны без раскрытия истории. Замер доступной памяти выполняется до загрузки и не является точным прогнозом пикового потребления или скорости.

Проверенные параметры сохраняются отдельно в `%LOCALAPPDATA%\CryptoBook\ai-runtime-profiles.json`; текст диалога, системная инструкция и вложения туда не попадают. Профиль связан с путём, размером и временем изменения модели, запрошенным контекстом, ОЗУ, CPU, GPU, доступными сведениями о видеодрайвере, ОС и сборкой движка. При следующей загрузке сохранённый вариант снова проходит пробную генерацию. **Подобрать заново** удаляет рабочие профили выбранной модели и запускает новую проверку. Ошибка записи профиля не прерывает уже работающую модель.

Проверка и реальные запросы выполняются в отдельном процессе. Его авария не завершает основной процесс CryptoBook. До первого фрагмента ответа автоматический режим может подобрать другие параметры и повторить запрос. После частичного ответа повтор не выполняется: текст остаётся в диалоге, а ошибка показана пользователю. Остановка, выгрузка, блокировка пространства и закрытие приложения завершают AI-процесс; Windows также завершает его при аварийном выходе основного процесса. Следующий запрос загружает модель заново.

## English

Open **Settings → AI assistant → Model settings**, enable the assistant and browse to a GGUF language model. No separate application or server is required. The **AI** title-bar button opens the right-side panel. **Attach files…** and drag-and-drop add documents or images as file cards; **Current document** attaches a snapshot of the entire open document. Documents are extracted as text; images use a matching mmproj GGUF found beside the model, with the vision encoder running in RAM on the CPU. Attachments remain in memory for follow-up questions and are cleared with the chat or workspace lock. Replies stream into the panel and can be copied, inserted or used to replace the original selection, with undo and a guard against stale edits. **Unload model** cancels generation and releases the text and vision models; idle unloading defaults to 10 minutes. Settings are remembered per model file, and chat messages and attachments are not persisted.

Memory placement defaults to automatic GPU layer offload with RAM for the remaining weights. Failed weight loads retry with fewer GPU layers, down to CPU only. CPU-only and manual modes are available in advanced settings. Text chat includes Gemma 4 turn formatting and filters thinking/channel markers from displayed answers.

For Gemma 4 E2B/E4B with partial GPU offload, Flash Attention is disabled automatically to avoid a fatal graph scheduler assertion in the bundled llama.cpp. GPU layers remain accelerated; this applies to model checks, text chat and image requests.

Drag the panel's left edge to adjust its width. Choose a GGUF file or a saved model in **Model settings**, then save. Switching starts a new chat and unloads the previous model. The selected model loads on the next request.

The reply token limit may exceed the context size; actual generation is capped at the remaining context after the prompt and history. Test and Save validate the same original settings and commit pending input first.

Automatic mode now probes loading, context creation and trial generation in an isolated process of the same executable. It can disable Flash Attention, reduce batches and GPU layers, use a CPU backend and, when allowed, reduce context. Manual GPU/context settings remain authoritative. Actual parameters, persistent warnings and a timestamped attempt history appear in both the panel and model settings. Metadata inspection has a 60-second timeout; each of at most 13 trial configurations has a 120-second timeout and can be cancelled.

Verified parameters are cached in `ai-runtime-profiles.json`, keyed by the model file, requested context, hardware, available driver information, OS and engine build. Cached parameters are checked again before use. **Retune** clears that model's runtime profiles. Chat data travels only through in-memory pipes; no conversation, system prompt or attachment is stored in the cache. Real generation is isolated too: failures before output can trigger automatic recovery; partial replies are kept without automatic repetition. Stop, unload and workspace locking close the worker, and a Windows job also terminates it if the main application exits abruptly.
