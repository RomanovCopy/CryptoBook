# Локальный AI-помощник

Доступен начиная с CryptoBook 1.1.4.4. GGUF-модели и vision-проекторы не входят в установщик и выбираются пользователем отдельно.

1. Откройте **Настройки → AI-помощник → Настройки модели** либо нажмите **AI** справа в заголовке и **Настройки модели**.
2. Включите помощника, нажмите **Обзор…** и выберите файл языковой модели `.gguf`. Файл проектора `mmproj` выбирать не нужно.
3. При желании нажмите **Проверить модель**, затем **Сохранить**. Дополнительные приложения, сервер и сетевые адреса не требуются.
4. Напишите запрос в правой панели. **Ctrl+Enter** отправляет запрос, **Остановить** прерывает генерацию.

Кнопка **Оформление чата** открывает выбор шрифта, размера (8–40), отдельных цветов текста вопросов и ответов и рамок сообщений. По умолчанию рамки выключены, цвета следуют текущей теме. Цвет можно выбрать в диалоге или ввести как `#RRGGBB`; пустое поле возвращает цвет темы. Шрифт и размер применяются также к полю ввода и раскрытому тексту рассуждений. Для блоков кода отдельно доступны **Шрифт блоков кода** и **Цвет текста блоков кода**; пустой цвет наследуется от текста сообщения. Эти параметры меняют в том числе уже показанные блоки, сохраняя исходный текст; строчный код и предпросмотр документов используют прежнее оформление. **Сбросить → Сохранить** возвращает исходное оформление. Эти настройки общие для моделей, сохраняются между запусками и применяются без очистки диалога и остановки ответа.

Флажок **Визуализировать Markdown** в этом же окне по умолчанию включён: вопросы и ответы показываются с заголовками, выделением, списками, цитатами, таблицами, ссылками и блоками кода. При выключении виден исходный текст с разметкой. Выбор сохраняется между запусками и меняет отображение уже существующих сообщений без очистки переписки, черновика, вложений и счётчика. При генерации оформление обновляется примерно раз в 200 мс; незаконченные блоки Markdown также отображаются. Шрифт, размер и цвета чата применяются к отображаемому документу, размер заголовков масштабируется, код по умолчанию моноширинный. **Копировать**, **Вставить выбранное** и **Заменить выделение** работают с исходным текстом отмеченных сообщений, включая Markdown. Счётчик и история для модели также используют исходный текст. HTML показывается как текст, Markdown-картинки не загружаются, ссылки открываются только по нажатию пользователя.

Флажки рядом с подписями **Вы** и **AI-помощник** позволяют отметить любой вопрос, ответ или несколько сообщений. **Выбрать всё** отмечает всю переписку с непустым текстом, **Снять выбор** снимает все отметки; без выбранных сообщений вставка, замена и копирование недоступны. Счётчик показывает число отмеченных сообщений. Несколько сообщений переносятся в порядке диалога с подписями участников и разделителями; одно сообщение переносится без дополнительной подписи. По умолчанию после каждого запроса выбран последний непустой ответ. Ручной выбор сохраняется при следующих запросах до очистки чата. Рассуждения модели и содержимое вложений в перенос не входят. Выбор не меняет историю, отправляемую модели, или счётчик контекста.

Под полем ввода показаны свободные токены контекста **текущего чата**, его заполнение и доступный лимит ответа. Вопросы, ответы, системный промпт и вложения используют одно окно контекста. При наборе значение с `≈` — оценка по UTF-8 с поправкой по последнему измеренному запросу; изображения точно учитываются после отправки. Во время генерации движок передаёт фактическое число входных и сгенерированных токенов, включая рассуждения, и реальный размер контекста после автоподбора памяти. Текстовый счётчик обновляется с небольшой задержкой, без загрузки модели при каждом вводе. Лимит ответа — верхняя граница, а не заранее занятые токены. Когда свободно не более 10% контекста (или 64 токенов для небольшого окна), появляется предложение начать **Новый чат**.

Кнопки **Очистить чат** и **Новый чат** очищают историю, черновик и вложения и сразу сбрасывают счётчик: заполнение становится нулевым, свободен весь фактический контекст модели. Служебные токены шаблона и системного промпта учитываются при вводе следующего вопроса или его отправке. Измерения предыдущего диалога в новый не переносятся. Переписка хранится только в памяти; обе кнопки удаляют её без архивирования, не выгружая модель.

Если **Отправить** недоступна, под полем запроса и в подсказке кнопки указана причина: помощник выключен, сообщение пустое, вложения читаются, выполняется предыдущий запрос или защищённое рабочее пространство заблокировано. Сохранённый зашифрованный снимок для последующего восстановления сам по себе не блокирует обычную работу и отправку новых запросов. При действительной блокировке пространства отправка, вложения и применение ответа недоступны; диалог и черновик очищаются при сбросе ключа.

Ширина панели меняется перетаскиванием её левой границы и сохраняется при закрытии и повторном открытии панели. При уменьшении окна ширина ограничивается доступным местом.

Модель выбирается в окне **Настройки модели**: укажите GGUF-файл или выберите ранее настроенную модель из списка и нажмите **Сохранить**. Параметры каждой модели сохраняются отдельно. Смена модели отменяет текущую генерацию, выгружает прежнюю модель и начинает новый диалог; выбранная модель загружается при следующем запросе.

Нажмите **Прикрепить файлы…** или перетащите файлы в панель. Документы и изображения показаны карточками с именем и размером; у изображений есть миниатюра. Кнопка **Текущий документ** прикладывает весь текст открытого документа как файл-снимок, включая несохранённые изменения. До отправки любое вложение можно убрать. Содержимое фиксируется при прикреплении и сохраняется в памяти диалога для последующих вопросов. Сохранённые изображения повторно включаются в текущий запрос модели при уточняющих вопросах.

Поддерживаются текстовые файлы, Markdown, RTF, DOCX, XamlPackage, PNG, JPEG, BMP, GIF и TIFF. Из документов извлекается текст. Для изображений нужна модель с поддержкой зрения и соответствующий `mmproj*.gguf` в той же папке; при единственном таком файле он подхватывается автоматически. Визуальный модуль работает на процессоре и использует ОЗУ; вручную задавать второй путь не требуется. При неподходящей модели запрос не отправляется, изображение остаётся прикреплённым. Максимум — четыре файла на сообщение, 32 МБ на файл и 500000 символов текста; изображения уменьшаются до 1280 пикселей по большей стороне. Пустой запрос с вложением получает стандартную команду анализа файлов.

Выбранные сообщения можно скопировать, вставить в текущую позицию курсора открытого редактора либо заменить ими текущее выделение. Документ и выделение выбираются при нажатии кнопки: их можно изменить после получения ответа, новый запрос не нужен. **Вставить выбранное** доступна при отмеченных сообщениях и открытом редакторе, **Заменить выделение** — дополнительно при выделенном тексте в документе. После применения курсор стоит за вставленным текстом; выбранные сообщения можно применить повторно. Вставка в обычный редактор и исходник Markdown поддерживает Ctrl+Z. В режиме предпросмотра Markdown достаточно перейти к исходнику. Режим «только чтение», генерация ответа и блокировка защищённого пространства запрещают изменение документа; причина недоступности показана в подсказке кнопки. Перед изменением проверяются актуальность документа, выделения и его редакции.

Во время распознавания картинки панель показывает **Обработка изображения…**, а при появлении текста — **Генерация ответа…**. Визуальный модуль использует процессор; обработка фотографии может занять заметное время до первого текста.

## Параметры и память

- Контекст и максимальная длина ответа задаются в токенах. Лимит ответа можно задать больше контекста: фактический ответ ограничивается оставшимся местом после запроса и истории. Например, контекст 4096 и лимит ответа 10000 сохраняются и работают вместе. Когда сам запрос с историей не оставляет места для ответа, помощник предлагает очистить диалог или увеличить контекст; сообщения не удаляются незаметно.
- Проверка модели и сохранение используют одинаковые правила проверки исходных параметров. Кнопки сначала принимают последние значения из полей ввода. Ошибки указывают конкретный параметр.
- Креативность: 0–2; меньшее значение даёт более предсказуемый ответ.
- По умолчанию память распределяется автоматически: число слоёв GPU подбирается по бюджету видеопамяти с запасом для контекста и рабочих буферов; остальные слои используют ОЗУ и процессор. При ошибке загрузки весов помощник повторяет загрузку с меньшим числом слоёв GPU, вплоть до CPU. Веса отображаются из файла в память средствами Windows, без обязательного копирования всего файла в ОЗУ.
- Для Gemma 4 E2B/E4B при частичном размещении на GPU автоматически отключается Flash Attention: это обходит аварийное завершение встроенного llama.cpp при подготовке вычислительного графа. Слои GPU продолжают использовать видеокарту; правило действует при проверке модели, в текстовом чате и при работе с изображениями.
- В дополнительных параметрах можно выбрать **Только процессор · ОЗУ** или вручную задать число слоёв GPU: 0 — процессор, -1 — все слои на видеокарте. Там же находятся рассуждения для Qwen/Gemma и инструкция для модели. Большой контекст увеличивает расход памяти; размер файла модели не равен потреблению видеопамяти.
- Параметры сохраняются отдельно для каждого файла. Ранее выбранные модели доступны в списке окна настроек.
- **Защита от повторяющихся ответов** включена по умолчанию и сохраняется отдельно для каждой модели в дополнительных параметрах поведения. Мягкий DRY-сэмплер подавляет растущие повторяющиеся последовательности; отдельный детектор с ограниченным буфером останавливает устойчивые дословные повторы в ответе и в рассуждениях. Различия в пробелах и переносах строк учитываются как один пробел. Сохраняются полезное начало и первое вхождение повторяющегося фрагмента; повторяющийся хвост исключается из копирования, вставки и дальнейшей истории. Панель показывает отдельную причину остановки, запрос не повторяется, проверенная конфигурация памяти сохраняется. Для намеренных повторов защиту можно отключить. Перефразированные смысловые повторы этот детектор не распознаёт.

Флажок **Разрешить развёрнутые рассуждения** управляет режимом поддерживаемых Qwen/Gemma. Рядом постоянно видно предупреждение: **Не все модели поддерживают отключение рассуждений**. **Проверить модель** использует текущее положение флажка; для применения в чате нажмите **Сохранить**. Для Gemma 4 E2B/E4B при отключении используется обычное начало ответа без пустого канала рассуждений; для старших Gemma 4 сохраняется их собственный формат отключения. Включение добавляет управляющий токен рассуждений. Описание форматов: [Google Gemma — Thinking mode](https://ai.google.dev/gemma/docs/capabilities/thinking).

Если модель выдаёт размеченные рассуждения, они поступают в отдельный сворачиваемый блок **Рассуждения модели** с рамкой и приглушённым цветом, независимо от положения флажка. Пока анализ идёт без итогового ответа, статус показывает **Модель рассуждает…**. Поддерживаются каналы Gemma, блоки `<think>` и канал analysis; учитывается и уже открытый канал в шаблоне запроса. Копирование, вставка и последующая история используют только итоговый ответ. Рассуждения без итогового ответа сохраняются в блоке, а панель поясняет, что можно увеличить лимит ответа. При остановке частичный анализ остаётся доступен; очистка чата и блокировка удаляют его вместе с сообщениями. Рассуждения передаются только в памяти, включая изолированный процесс, и не записываются в настройки или журналы. Для текста и изображений используются одинаковые правила разделения. Если модель выдаёт обычный текст без границ каналов, надёжно отделить анализ от ответа по одним словам нельзя.
- **Выгрузить модель** останавливает текущую генерацию и освобождает веса и контекст. Следующий запрос загружает модель заново.
- По умолчанию модель выгружается после 10 минут бездействия; 0 отключает автовыгрузку. Проверка простоя выполняется каждые 15 секунд. Активная генерация не считается простоем.
- Изменение параметров выбранной модели, смена модели и отключение AI очищают диалог и выгружают модель. Изменение оформления и тайм-аута простоя сохраняет диалог. Блокировка защищённого рабочего пространства очищает диалог, черновик и приложенный контекст, отменяет генерацию и выгружает модель. При закрытии приложения нативные ресурсы освобождаются.

Обработка выполняется локально через LLamaSharp/llama.cpp с Vulkan и CPU в отдельном процессе того же `CryptoBook.exe`. Сервер и сеть не используются. Модель загружается из выбранного файла и не копируется. Диалог и вложения передаются по каналу в памяти и не сохраняются на диск приложением. Настройки без содержимого документов находятся в `%LOCALAPPDATA%\CryptoBook\ai-settings.json`. Модели не входят в дистрибутив. Поддержка конкретной архитектуры GGUF зависит от встроенного движка; вызов инструментов моделями в этой версии не подключён. Выгрузка освобождает также визуальный модуль; очистка диалога, блокировка и смена модели удаляют вложения из панели и истории.

## Тест производительности и повышенная нагрузка

В настройках модели доступен раздел **Производительность AI**. Разрешение **Разрешать повышенную нагрузку при генерации** по умолчанию выключено и сохраняется отдельно для каждой модели. По умолчанию повышенная нагрузка также разрешена только при питании от сети.

1. Выберите модель и контекст, включите разрешение на повышенную нагрузку и нажмите **Протестировать производительность**. Флажок меняет только черновик настроек; запуск теста не сохраняет согласие для последующих запросов.
2. Тест проверит совместимость с полным выбранным контекстом, затем сравнит обычный режим и до трёх вариантов числа потоков CPU и производительного режима Windows для процесса AI. Слои GPU и размеры пакетов сохраняют параметры совместимого варианта и существующий запас видеопамяти. Контекст не уменьшается для улучшения результата.
3. Каждый вариант прогревается и выполняет две генерации на одинаковом служебном тексте. Документы, вложения, системная инструкция и переписка пользователя не используются. Отдельно измеряются обработка запроса и генерация в токенах в секунду, пик рабочего набора ОЗУ процесса и наблюдаемый объём видеопамяти (опрос примерно раз в 200 мс). Загрузка весов и прогрев не входят в скорость генерации.
4. При выигрыше от 5% сохраняется ускоренный профиль. Для сравнения используется одинаковый объём обработки и генерации, нормированный по измеренным скоростям. При меньшем выигрыше выбирается обычный режим. Последний результат показывается при повторном открытии настроек.
5. Нажмите **Сохранить**, чтобы разрешение применялось к последующим ответам. Повышенная нагрузка используется только при наличии подходящего измеренного профиля. Снятие разрешения и сохранение возвращает обычный режим, сохраняя переписку и черновик.

Одна измерительная проба ограничена 90 секундами, весь тест — шестью минутами. Между прогонами приложение ожидает завершения прежнего процесса AI и восстановления бюджета памяти, прежде чем рассчитывать ограничения нового процесса. **Остановить**, закрытие настроек и выгрузка модели отменяют тест; незавершённый тест не заменяет прежний результат. При изменении файла модели, оборудования, драйвера, контекста или сборки движка ранее измеренный профиль не применяется без новой проверки. Показанный последний тест служит историей измерения, а не подтверждением пригодности профиля для изменившейся системы.

Ограничения затрагивают только дочерний процесс AI. Во время повышенной нагрузки ему доступно не более 80% CPU; приоритет планировщика остаётся обычным. План питания Windows, частоты и настройки других программ не меняются. Производительный режим процесса действует только во время операции и восстанавливается после неё.

Тест и ускоренная генерация оставляют резерв ОЗУ: 1/8 физической памяти, минимум 1 ГиБ и максимум 4 ГиБ. Коммит процесса AI ограничивается доступной физической и коммитируемой памятью за вычетом этого резерва. Дополнительно контролируются свободная память системы и бюджет видеопамяти AI. При нехватке памяти операция AI останавливается с пояснением. Если ограничения ускорения установить невозможно, генерация продолжается в обычном режиме; само согласие без измеренного профиля не включает ограничения предварительной проверки модели. При отключении питания от сети ускорение отменяется; уже начатый ответ автоматически не повторяется. CryptoBook не закрывает другие программы и не освобождает память завершением чужих процессов. Короткий тест не гарантирует такую же скорость на длинном диалоге или при изменении фоновой нагрузки.

При повторном запросе к уже загруженной модели лимит учитывает коммит, уже занятый процессом AI: свободный бюджет ограничивает дополнительные выделения, а не обнуляет ранее разрешённую память весов.

## Автоматическая проверка и восстановление

Режим **Автоматически** проверяет загрузку модели, создание контекста и короткую генерацию на служебном запросе. При неудаче последовательно отключает Flash Attention, уменьшает пакеты обработки и число слоёв GPU, пробует CPU. Если включено **Разрешать автоматическому режиму уменьшать контекст**, дополнительно проверяет меньший контекст, вплоть до 512 токенов. Заданное пользователем значение контекста сохраняется; фактическое значение и предупреждение о меньшей вместимости истории видны в панели и настройках. История и вложения не обрезаются автоматически. В ручном режиме число слоёв GPU и контекст не подбираются заново.

Первая проверка требует дополнительного времени: чтение метаданных ограничено 60 секундами, каждая пробная генерация — 120 секундами. Проверка конечна (не более 13 вариантов), её можно остановить. Панель **Проверки, изменения параметров и причины сбоев** показывает время, параметры каждой попытки, код аварийного выхода или понятную причину отказа. Основные параметры, переход на CPU, отключение Flash Attention и уменьшение контекста видны без раскрытия истории. Замер доступной памяти выполняется до загрузки и не является точным прогнозом пикового потребления или скорости.

Проверенные параметры сохраняются отдельно в `%LOCALAPPDATA%\CryptoBook\ai-runtime-profiles.json`; текст диалога, системная инструкция и вложения туда не попадают. Профиль связан с путём, размером и временем изменения модели, запрошенным контекстом, ОЗУ, CPU, GPU, доступными сведениями о видеодрайвере, ОС и сборкой движка. При следующей загрузке сохранённый вариант снова проходит пробную генерацию. **Подобрать заново** удаляет рабочие профили выбранной модели и запускает новую проверку. Ошибка записи профиля не прерывает уже работающую модель.

Проверка и реальные запросы выполняются в отдельном процессе. Его авария не завершает основной процесс CryptoBook. До первого фрагмента ответа автоматический режим может подобрать другие параметры и повторить запрос. После частичного ответа повтор не выполняется: текст остаётся в диалоге, а ошибка показана пользователю. Остановка, выгрузка, блокировка пространства и закрытие приложения завершают AI-процесс; Windows также завершает его при аварийном выходе основного процесса. Следующий запрос загружает модель заново.

## English

Open **Settings → AI assistant → Model settings**, enable the assistant and browse to a GGUF language model. No separate application or server is required. The **AI** title-bar button opens the right-side panel. **Attach files…** and drag-and-drop add documents or images as file cards; **Current document** attaches a snapshot of the entire open document. Documents are extracted as text; images use a matching mmproj GGUF found beside the model, with the vision encoder running in RAM on the CPU. Attachments remain in memory for follow-up questions and are cleared with the chat or workspace lock. Replies stream into the panel and can be copied, inserted at the current cursor or used to replace the current selection, with undo and document validation immediately before applying. The document and selection can be chosen after the answer arrives; applying the same answer again remains available. Markdown preview must be switched to the source editor before applying. **Unload model** cancels generation and releases the text and vision models; idle unloading defaults to 10 minutes. Settings are remembered per model file, and chat messages and attachments are not persisted.

Use the checkboxes beside questions and answers to choose any messages, or **Select all** to transfer the entire conversation. **Insert selected**, **Replace selection** and **Copy** use the checked messages in conversation order. Multiple messages include participant labels and separators; a single message keeps its original text. The latest nonempty answer is selected automatically until you change the selection manually. Manual selection persists across follow-up requests and resets with the chat. **Clear selection** unchecks all messages and disables transfer commands. Reasoning and attachment contents are excluded; selecting messages does not change the history sent to the model or its token budget.

Memory placement defaults to automatic GPU layer offload with RAM for the remaining weights. Failed weight loads retry with fewer GPU layers, down to CPU only. CPU-only and manual modes are available in advanced settings. Text chat includes Gemma 4 turn formatting and filters thinking/channel markers from displayed answers.

For Gemma 4 E2B/E4B with partial GPU offload, Flash Attention is disabled automatically to avoid a fatal graph scheduler assertion in the bundled llama.cpp. GPU layers remain accelerated; this applies to model checks, text chat and image requests.

Drag the panel's left edge to adjust its width. Choose a GGUF file or a saved model in **Model settings**, then save. Switching starts a new chat and unloads the previous model. The selected model loads on the next request.

The reply token limit may exceed the context size; actual generation is capped at the remaining context after the prompt and history. Test and Save validate the same original settings and commit pending input first.

**Protect against repetitive answers** is enabled by default and saved per model in advanced behavior settings. A mild DRY sampler discourages growing repeated sequences; a separate bounded detector stops sustained verbatim loops in both answers and reasoning, treating whitespace and line breaks alike. The useful prefix and first occurrence are kept; the repeated tail is excluded from copying, insertion and future conversation history. A distinct status explains the stop, without retrying the request or rejecting the verified memory configuration. Disable protection for intentional repetition. Paraphrased semantic repetition is not detected.

Automatic mode now probes loading, context creation and trial generation in an isolated process of the same executable. It can disable Flash Attention, reduce batches and GPU layers, use a CPU backend and, when allowed, reduce context. Manual GPU/context settings remain authoritative. Actual parameters, persistent warnings and a timestamped attempt history appear in both the panel and model settings. Metadata inspection has a 60-second timeout; each of at most 13 trial configurations has a 120-second timeout and can be cancelled.

Verified parameters are cached in `ai-runtime-profiles.json`, keyed by the model file, requested context, hardware, available driver information, OS and engine build. Cached parameters are checked again before use. **Retune** clears that model's runtime profiles. Chat data travels only through in-memory pipes; no conversation, system prompt or attachment is stored in the cache. Real generation is isolated too: failures before output can trigger automatic recovery; partial replies are kept without automatic repetition. Stop, unload and workspace locking close the worker, and a Windows job also terminates it if the main application exits abruptly.
