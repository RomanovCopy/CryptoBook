# Local AI smoke

`--performance-generate <ai-settings.json> <output-directory>` проверяет реальную генерацию на выбранной модели с сохранёнными контекстом и режимом производительности, используя отдельный кэш. `--performance-benchmark` с теми же аргументами предварительно выполняет настоящий тест производительности и затем проверяет выбранный профиль генерацией. Системная инструкция заменяется пустой, запрос служебный, пользовательские настройки и кэш не меняются. Отчёт содержит только технические параметры, измерения и ответ на служебный запрос.

`--performance-ui <output-directory>` проверяет настоящий WPF-раздел производительности: сбалансированный режим по умолчанию, недоступность подбора в экономичном режиме, включение кнопки в оптимальном режиме, запуск и отмену, отсутствие автоматического сохранения режима, сохранение и повторное открытие настроек. Создаёт PNG светлой/тёмной темы и минимального размера окна, отдельные настройки и `result.json`. Измерительный worker в этом сценарии детерминированный; GGUF-модель не нужна, фактическая скорость нативного движка им не проверяется. Пользовательские настройки не меняются.

Проверяет встроенный движок CryptoBook без LM Studio, сервера и HTTP: генерацию, отмену, выгрузку во время генерации, освобождение памяти и повторную загрузку. Базовый сценарий ниже использует нативный движок напрямую; `--adaptive` проверяет изолированный режим приложения.

```powershell
dotnet restore tools\LocalAiSmoke\LocalAiSmoke.csproj --locked-mode
dotnet run --project tools\LocalAiSmoke\LocalAiSmoke.csproj -c Release --no-restore -- 'D:\Models\model.gguf' 'artifacts\local-ai-result.json' auto
```

Третий аргумент — `auto` (также по умолчанию) или число слоёв GPU для ручного режима (0 для CPU, -1 для всех слоёв). Отчёт содержит план распределения памяти. Замеры `nvidia-smi` необязательны и выполняются только диагностической утилитой; сам движок не запускает внешних процессов.

Быстрая проверка одной модели: `--probe <model.gguf> <report.json>`. Проверяет ответ при автоматическом распределении памяти и контексте 4096, затем выгрузку. Тайм-аут — пять минут.

Аргумент `cpu` после пути отчёта включает проверку только на процессоре. Нативная диагностика выводится в stderr, чтобы при аварийном завершении движка сохранить причину сбоя; используйте перенаправление `2> native.log`.

`--adaptive <model.gguf> <output-directory>` проверяет производственный автоподбор: генерацию в дочернем процессе, отмену с его завершением, повторное использование и проверку сохранённого профиля, обнаружение завершённого worker, отсутствие нативного движка в родителе и завершение worker после принудительного закрытия его владельца. `--adaptive-cpu` запускает тот же сценарий без GPU (без автоматического кеша). Настройки и профили проверки находятся только в каталоге отчёта. WPF-сценарии также используют изолированный движок и отдельное тестовое хранилище профилей.

Для рендера настоящих WPF-элементов в светлой и тёмной темах:

```powershell
dotnet run --project tools\LocalAiSmoke\LocalAiSmoke.csproj -c Release --no-restore -- --ui 'D:\Models\model.gguf' 'artifacts\ai-ui-preview'
```

Рендер использует пример диалога, не запускает генерацию и не сохраняет настройки. Это проверка компоновки WPF; ручные клики пользователя не имитируются.

`--chat-appearance <output-directory>` проверяет отдельное окно оформления и настоящие шаблоны сообщений: выбор шрифта и размера, разные цвета вопросов и ответов, рамки вкл./выкл., светлую/тёмную темы, минимальный размер окна и сохранение текущего диалога. Нажимает кнопку сохранения через WPF UI Automation и повторно читает настройки. Затем вызывает кнопки **Очистить чат** и **Новый чат**, проверяя очистку истории, черновика и вложений и сброс заполнения контекста до нуля. Модель не нужна; настройки, отчёт `result.json` и PNG создаются только в каталоге проверки.

Сценарий также переключает **Визуализировать Markdown** через флажок в настоящем окне, сохраняет оба значения и повторно читает их с диска. Проверяет таблицу и выделение в ответе, отображение исходной разметки при выключении, шрифт и цвет документа и неизменность исходного текста и счётчика токенов. Снимки `chat-markdown-*.png` показывают оба режима и обе темы.

Затем проверяет флажки выбора вопросов и ответов, привязки и счётчик выбранных сообщений, порядок переноса, исключение рассуждений и недоступность выбора пустого ответа. Через UI Automation нажимает **Выбрать всё** и **Снять выбор**, проверяет отключение копирования без выбранных сообщений и сброс выбора при очистке чата. Снимки `chat-selection-*.png` показывают обычную ширину и узкую панель 280 пикселей в тёмной теме.

Регрессия проверки/сохранения и смены модели в настройках:

```powershell
dotnet run --project tools\LocalAiSmoke\LocalAiSmoke.csproj -c Release --no-restore -- --settings-regression 'D:\Models\first.gguf' 'D:\Models\second.gguf' 'artifacts\ai-settings-regression'
```

Открывает настоящее WPF-окно, вызывает кнопки через WPF UI Automation, сохраняет контекст 4096 и лимит ответа 10000, выбирает модели в настройках и получает реальные ответы обеих моделей. Проверяет отклонение некорректного контекста и нечислового ввода. Настройки записываются только в каталог отчёта; пользовательский `ai-settings.json` не меняется. Итог — `result.json`.

`--send-button <model.gguf> <output-directory>` проверяет настоящее поле ввода и кнопку **Отправить** при запуске с ожидающим восстановления зашифрованным снимком. Использует реальный `AutoKeyResetService` с подставным снимком без файлового ввода-вывода. Вводит текст, вызывает кнопку через WPF UI Automation, получает ответ модели и проверяет доступность повторной отправки. Отчёт и снимки панели сохраняются в каталоге проверки; пользовательские настройки и защищённые документы не затрагиваются.

Этот сценарий также проверяет передачу фактических счётчиков токенов из нативного процесса: исходный запрос, рост числа токенов ответа и уменьшение свободного контекста. Числа сохраняются в `native_token_usage` отчёта.

После ответа открывает собственный тестовый документ и вызывает настоящие кнопки **Заменить выделение** и **Вставить ответ** через WPF UI Automation. Проверяет выделение после получения ответа, отмену замены и повторную вставку того же ответа. Снимки `apply-*.png` показывают активность кнопок и результат изменения документа; пользовательские документы не открываются и не сохраняются.

`--reasoning-ui <model.gguf> <output-directory>` дополнительно переключает рассуждения в настоящем WPF-окне, сохраняет и заново читает профиль, проверяет ответы в последовательности выкл./вкл./выкл. и отдельный блок анализа, если модель его выдала. Флажок вызывается через UI Automation. `--reasoning-probe` сравнивает форматы запроса напрямую, читает шаблон из GGUF и сохраняет сырой вывод только собственных служебных запросов в каталог отчёта; пользовательский чат не используется.

`--attachments <model.gguf> <output-directory>` проверяет RTF/DOCX, отправку документа через модель представления, распознавание синтетической картинки, повторный вопрос по изображению и выгрузку во время генерации с изображением. Нужна vision-модель с единственным соответствующим mmproj в её папке. Создаёт только собственные тестовые файлы и настройки в каталоге отчёта.

`--image-profile <ai-settings.json> <image> <output-directory> [max-edge]` повторяет отправку конкретного изображения через команды панели с выбранным сохранённым профилем. Настройки и исходный файл не меняются; отчёт содержит параметры без системного промпта, размеры, состояния панели, время, ответ и результат выгрузки. Необязательный `max-edge` уменьшает только снимок в памяти для сравнительной диагностики. Вместо пути изображения можно передать `-` для синтетической картинки. Это проверяет случай, когда при ненулевой температуре первым выбирался токен завершения и панель сообщала о пустом ответе.

`--resources <ai-settings.json> <output-directory>` измеряет нагрузку при генерации текста с выбранным профилем, шесть секунд простоя с загруженной моделью и четыре секунды после выгрузки. Лимит диагностического ответа — 512 токенов, общий тайм-аут — три минуты; сохранённые настройки не меняются. В `result.json` попадают время до первого видимого текста, ответ, план размещения слоёв, CPU и память процесса, а также общие показатели GPU из `nvidia-smi`. Дополнительный процесс измерения запускает только диагностическая утилита, не приложение CryptoBook.
